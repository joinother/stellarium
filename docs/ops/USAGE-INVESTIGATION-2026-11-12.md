## 实际服务链路

- nginx 80/443 提供官网；HTTP 跳转 HTTPS，未知 Host 默认拒绝。
- `/v1/` 是 TLE/目录静态镜像，每 3 小时刷新，HTTP 缓存 1800 秒。
- `/nw/` 转发至 `127.0.0.1:8090` 的今夜星 Node 天气服务；Key 保留在服务器。
- 天气按 0.5° 网格共享缓存：24 小时预报 30 分钟，168 小时预报 3 小时；支持落盘。单点、网格、世界视图会扇出为实际和风请求。
- `127.0.0.1:8080` 仍是另一个 staging 资源服务，它的 `publicService:false` 不代表网站及 `/v1/` 未上线。
- AI 用于服务器内容安全审核，不是本次用户聊天产生的应用服务请求。

## 放大原因

### 1. 状态页触发反馈循环

`skyinstrument-status-page.timer` 每 5 分钟执行；生成器每次原子替换 `/srv/skyinstrument/status/index.html`。`quickcheck.timer` 每 10 分钟执行，扫描 nginx root/alias，按文件 size+mtime 判断变化。

生产 `file-hashes.json` 包含状态页。18:40 巡检报告明确列出三个目录：status、website/current、tle-mirror/v1；该轮只有 status/index.html 文本变化，仍执行完整巡检。状态页展示的时间、负载与用量变化又为下一轮提供变化来源。

每小时最多 6 次的限制与每 10 分钟执行的频率相同，无法消除此循环。全量文件巡检与业务探针、付费内容审核耦合，导致低成本状态变化触发高成本工作。

### 2. 同一误报重复送 AI

生产与本地 `deploy/server/skyinstrument-content-audit` SHA-256 一致。其规则命中复核每轮最多取 4 个文件，未按“文件内容哈希 + 规则版本 + 模型/提示词版本”缓存结论。

最新报告中隐私政策正常文字“代理”“网络”“复制”“唯一”“未成年”等仍命中宽泛词库；app-privacy.html、privacy.html、privacy.txt 在没有内容变化时也进入重复复核。状态页变更还可能进入额外自由审查。每日全页轮审也增加调用，但不是唯一来源。

300 次是当前本地上限检查，今天已触发降级。不是严格跨进程原子预算：quickcheck、content-audit、fullscan 使用不同锁文件；用量读改写没有共同锁。部分模型异常分支不记录调用，不能保证供应商账单绝不超过本地计数。

### 3. 巡检直接请求付费天气

完整巡检无条件进入 `check_api_endpoints()`；默认接口包括 healthz、grid、week、world、wx。其 40 次/小时预算计算的是代理入口请求，不是和风实际回源；函数内部 `used` 不随循环递增，429 重试也不单独消费预算。

`/v1/world` 包含 75 个城市，一次入口请求在全部缓存失效时可产生最多 75 次回源，部分相同网格可复用。30 分钟缓存无法阻止持续运行的巡检在每次缓存到期后再次刷新整组；失败点可能更频繁重试。不能把“探测 5 个接口”理解为“最多调用和风 5 次”。

旧版服务把缺少 lat/lon 的 `Number(null)` 当成 0。今天 99 次七天预报 HTTP 400 全部发生在 0,0，节奏与巡检一致。week 无负缓存；24h 部分失败只负缓存 10 分钟。现有天气日志和代理预算时间序列支持内部周期调用；审计配置文件未读取，不假称已看到它的具体内容。

### 4. 线上仍为旧天气版本

生产仅有 server.js，SHA-256 为 `b202b58ba80ea4fcc156fcb31a90b110b1b47e287c0b290ef888aaabb655e689`，与星象仪仓库旧副本、今夜星仓库新版均不同。当前进程自 11 月 11 日 16:25 启动，重启计数 0。

线上没有今夜星新版 limits.js 调度器，只有每个 grid/world 请求内部的分批并发，没有跨请求 single-flight 或全局 6 并发队列；没有每日和风硬预算、429 全局退避。此前本地/远端仓库已准备部分改进，不等于已部署。

## 安全现状与漏洞

已核实 nginx：每 IP 15 请求/秒、burst 30、20 连接；仅 GET/HEAD；TLS1.2/1.3；状态页 Basic Auth。内容规则、变更哨兵、每日全量/全文巡检、日报与镜像新鲜度检查均存在。08:00 日报显示当前实际内容拦截 0 条，处置记录为演练；不能把“有自动处置脚本”说成“已自动封禁”。备份/留存任务存在不代表本次已验证恢复能力。

天气 API 单 IP 120 次/小时，但线上 Node 直接信任 XFF 第一个值，nginx 又追加 `$proxy_add_x_forwarded_for`。调用方能伪造首个 XFF 绕过 Node 的 IP 配额；nginx 自己的真实连接 IP 限流仍在。入口次数也不能限制 world/grid 的付费扇出。

生产天气 Node 仍由 root 运行，虽有 NoNewPrivileges、PrivateTmp、ProtectHome、ProtectSystem=strict，写目录仍包括整个 /var/log 和 /var/lib/nightwindow。非 root 模板尚未部署。

18:30 访问聚合有 1572 请求、261 个 IP、126 个 429；所谓 scan_hits=331 实为 403+444 状态计数，不是 331 次已确认攻击。API 摘要仅列 `/v1/.env` 探测，未列天气业务路径，支持“未发现用户天气访问暴增”的判断；聚合只读取当前日志、只保留前 8 路径，不能据此排除所有异常访问。
