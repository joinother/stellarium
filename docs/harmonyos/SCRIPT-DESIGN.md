# HarmonyOS 脚本与录制设计

## 目标

- 播放脚本时把星图作为唯一主内容，普通 Dock、面板、详情卡片和快捷控件暂时隐藏。
- 录制时默认进入与播放一致的专注界面，只保留录制状态、暂停/继续和停止；需要操作搜索、定位、图层、时间等业务时，通过录制条临时展开统一 Shell，完成操作后可再次收起。
- 脚本字幕继续由 Stellarium 核心 `LabelMgr` 绘制，ArkUI 只负责控制和安全区，不建立第二套字幕渲染链。
- 所有控制命令继续走同一个 C++ 命令桥，便于 ArkUI、CLI 和后续自动化使用。

## 状态模型

| 状态 | 可见界面 | 可用操作 |
| --- | --- | --- |
| 空闲 | 统一响应式 Shell | 所有普通功能 |
| 脚本准备中 | 简化脚本控制条 | 停止 |
| 脚本播放中 | 简化脚本控制条 | 调整脚本速度、停止 |
| 录制中 | 简化录制控制条；可临时展开统一 Shell | 操作星图、展开业务面板、暂停/继续录制、停止 |
| 录制回放中 | 简化脚本控制条 | 调整速度、停止回放 |

Qt 6 的脚本引擎没有可靠的暂停/继续接口，因此原生 `.ssc` 脚本只有调速和停止；ArkUI 录制回放使用自己的时间轴，支持暂停/继续、调速和停止。两种会话不能同时存在。

## 会话状态

脚本功能使用互斥会话，而不是由多个按钮分别猜测状态：

| 会话 | 核心所有者 | ArkUI 外壳 | 结束条件 |
| --- | --- | --- | --- |
| 空闲 | 用户/核心 | 完整响应式 Shell | 启动后默认状态 |
| 原生脚本 | `StelScriptMgr` | 简化脚本条 | 核心报告脚本结束，或用户停止 |
| 命令录制 | ArkUI 录制器 | 简化录制条；按需展开 Shell | 用户停止或页面销毁 |
| 录制回放 | ArkUI 时间轴 + 核心命令桥 | 简化脚本条 | 所有命令完成、失败或用户停止 |

脚本列表、录制列表和视频帧序列属于“脚本工作台”面板，不属于播放态 UI。播放态不能打开普通面板，避免面板刷新、选中对象避让和传感器回调改变脚本镜头；录制态展开 Shell 后才允许调用业务面板。

## 录制格式

新录制命令使用如下字段：

```json
{"c":"命令名","p":"参数","t":1234}
```

`t` 是相对于录制开始时间的毫秒数。旧版只有 `c` 和 `p` 的文件仍然可读，回放时使用小的兼容间隔。视图连续拖动、陀螺仪逐帧姿态命令仍不写入录制文件，避免产生数千条无意义记录；离散缩放、搜索、选择、时间、位置、夜间模式和开关会通过统一命令记录入口写入时间轴。

录制与脚本播放互斥。录制只保存执行成功的命令；暂停期间不写入命令，恢复后时间戳扣除暂停时长。这样录制文件描述的是用户业务操作，而不是 ArkUI 重试、传感器采样或录制管理动作。

录制回放的速度只改变时间轴的虚拟流逝速度。切换速度时以当前虚拟时间为锚点重新排程，命令的 `t` 原值保持不变；暂停时冻结虚拟时间，继续后扣除暂停时长。

## 播放原则

1. 播放请求成功受理后立即进入专注模式，避免普通 UI 与字幕、星图争夺注意力。
2. ArkUI 轮询 `getScriptStatus`，以核心实际状态结束专注模式，不以启动回调或固定延时猜测脚本是否结束。
3. 录制回放按 `t` 顺序调度命令，避免原实现一次性发送导致时间轴失真。
4. 失败或用户停止时清理回放定时器、脚本状态和专注界面。

脚本运行期间由 Qt 线程上的专用心跳独占原生帧提交；普通 `fpsTimer` 会被暂停，Qt 图形场景的重复 `app.update()/app.draw()` 路径也会跳过。脚本结束后恢复普通帧定时器。这样脚本等待、字幕刷新和 ArkUI 命令轮询仍能工作，同时不会把同一帧绘制两次。

## 资源与字幕

脚本中文 `.qm` 文件每次启动通过资源引导刷新到应用沙箱，避免升级安装保留旧 `filesDir` 后继续显示旧字幕。字幕内容和排版仍由源项目脚本翻译与 `LabelMgr` 统一管理。

不把整套脚本字幕改成 ArkUI `Text`：字幕可能绑定天球坐标、随投影移动、自动过期，并由脚本动态创建或删除。ArkUI 的原生 `Text` 适合脚本状态条、错误提示和业务面板；Stellarium 的 `LabelMgr` 继续负责天球内字幕，当前只通过安全区参数避免挖孔屏遮挡。这样不会出现两套字幕状态、坐标系和生命周期互相竞争。

## 源码能力盘点

当前源码脚本目录包含 84 个 `.ssc`、6 个 `.inc`，另有脚本测试、声音、视频和数据辅助文件。脚本实际使用的业务能力集中在以下几组：

- 视图与导航：`StelMovementMgr`、`core.moveToRaDec`、`core.moveToAltAzi`、缩放、跟踪、地平线方向和投影。
- 时间与位置：`core.setDate`、`core.setJDay`、`core.setTimeRate`、`core.setObserverLocation`、时区和实时模式。
- 天体与星表：`core.selectObjectByName`、`core.getObjectInfo`、`SolarSystem`、`StarMgr`、`NebulaMgr`、`Satellites`。
- 显示图层：`ConstellationMgr`、`GridLinesMgr`、`LandscapeMgr`、`StelSkyDrawer`、`LabelMgr`、`MarkerMgr`、`ScreenImageMgr`。
- 日历与天文计算：源码脚本使用 `Calendar`、中国历法、波斯历、巴哈伊历、印度历和法国共和历等计算对象。
- 多媒体与输出：脚本可调用屏幕字幕、屏幕图片、声音、视频、截图和脚本输出；HarmonyOS 运行时仅允许使用包内或应用沙箱资源，不自动访问外部链接。

因此业务层应继续坚持“核心能力在 C++、界面控制在 ArkUI、自动化统一走命令桥”的边界。新增脚本能力先补充命令目录和离线权限说明，再接入 ArkUI；不要在 ArkUI 重新实现天文计算或字幕渲染。

## 脚本能力分层

- **脚本源文件**：`scripts/*.ssc` 是演示流程，`*.inc` 是共享函数或数据；脚本通过 `StelMainScriptAPI` 调用时间、位置、视角、选择、图层、星表、天文计算、字幕和输出能力。
- **脚本资源**：`.qm` 提供脚本翻译；包内图片、音频、视频和数据文件由资源引导复制到应用沙箱。HarmonyOS 运行时不默认访问外部链接，网络型脚本必须单独标记并保持离线替代路径。
- **核心业务**：天体计算、坐标变换、投影、天球渲染、`LabelMgr` 和脚本解释执行留在 C++/Qt 核心，保证桌面、ArkUI 和 CLI 的结果一致。
- **交互控制**：ArkUI 只负责状态显示、按钮、触摸/键鼠输入、专注外壳和安全区；所有改变核心状态的操作经统一命令桥执行。
- **CLI/自动化**：命令目录是唯一公开控制面。新增脚本或插件能力先登记命令、参数编码、返回结构、离线属性和确认要求，再接入 ArkUI，避免出现只能点击、不能自动化的孤立功能。

当前不支持直接把任意 `.ssc` 脚本录成可逆的逐帧电影：录制器记录的是业务命令，不记录连续拖动和陀螺仪采样。需要视频输出时走独立的帧序列录制；需要可重复的交互流程时走命令录制。
