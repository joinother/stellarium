# 托管协议更新与重新签署

更新日期：2026-09-09。

当前方案：由华为托管处理协议更新提醒；已撤回先前自行增加的30秒轮询、运行中重签遮罩及全应用暂停/恢复机制。下述当前行为取代本文件此前方案，历史构建留在 CHANGELOG。

## 约定

协议版本变化通过 AGC 的协议发布流程管理，以设备 Privacy Manager 返回的当前配置为准。不自行清除签署记录、不调用 disableService 模拟版本更新、不改本地布尔值伪造同意，不创建第二个 Ability 或另一套协议正文弹窗。用户主动撤回同意仍沿用原入口。

官方依据（华为开发文档 MCP）：[隐私管理服务](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/store-privacy)、[PrivacyManager 接口](https://developer.huawei.com/consumer/cn/doc/harmonyos-references/store-privacymanager)。`REQUIRE_RESIGNING_VERSION_UPDATE=2` 表示需要重新签署；隐私声明与用户协议各有类型、编号和版本。系统托管首次自动弹窗与主动请求必须避免重复；重新签署通过官方 requestAppPrivacyConsent 完成。

## 平台规则与当前实现

- 用户提供的华为说明截图写明：未关联在架版本时，生成协议覆盖原内容；关联在架版本时需审核通过后才生效，并选择是否需要明示用户重新授权。选择“需要”后，用户使用应用时收到更新提示；选择“不需要”则不提示。是否需要重新授权应根据实际处理规则变化判断，不在应用中统一强制。
- MCP核实了托管首次自动弹窗、签署结果查询和公共事件接口；未检索到要求每30秒查询的规定。截图对应AGC网页本轮抓取超时，平台更新说明以用户提供的截图为依据，不声称已从MCP取得相同全文。

- `PrivacyConsent` 统一核验所有配置的协议：至少有隐私声明，每个隐私声明/用户协议均有同类型、同 id、同版本的同意结果。缺少任一用户协议、旧版本、结果2、拒绝、未知类型及接口异常均不放行；同版本互相冲突的签署结果也不放行。
- 弹窗返回结果与随后查询的当前配置都要通过核验，避免弹窗打开期间协议再次更新。原主进程、Qt 子进程、定位、传感器入口继续使用同一判断函数。
- 不再定时检查协议，不因前台查询结果变化触发自制全屏遮罩或全应用暂停。删除相应监测器、AppStorage状态、重签UI、业务CLI全局阻断及专用多语言引导。正常前后台生命周期保持原有逻辑。
- 保留启动前、Qt子进程入口和敏感功能入口的同意核验，以及系统签署事件后的复核。保留启动服务异常时手动重试官方弹窗、用户主动撤回入口；这些不是协议更新的另一套托管机制。
- 保留窗口恢复的同意门禁及待恢复请求，核验通过后只恢复一次，不另建窗口。
- 只读 `getPrivacyConsentState` 保留，返回 currentAgreementsAccepted、nativeInitialized、foreground；去除自制状态 renewalRequired。没有自动同意命令，不输出协议全文或设备身份信息。

## 验证及发布边界

- 72项隐私、启动、审核整改及锚定回归通过。已将旧的轮询/遮罩测试替换为“不创建协议监测定时器、不额外全局暂停、不创建重签遮罩”，继续验证主/子进程门禁、多协议、只读CLI及待恢复窗口。
- 生成工程同步、CompileArkTS 和 Release assembleHap 成功（14.951秒）；签名仍Default，版本仍1000052，签名配置SHA未变化。
- 未修改 AGC 已发布协议、未撤回真实用户同意，未做正式协议版本切换。因此自动化测试通过不等于真实云端更新链路已经验收。
- 本轮首次设备列表只有模拟器；主动重新连接既有无线Pad成功后，已覆盖安装精简版。只读CLI先返回未同意、原生未初始化，后收到系统签署事件并核验成功，再进入Qt；本代理未点击同意。最终ready=true、2560×1600，currentAgreementsAccepted=true、nativeInitialized=true，输出不再含renewalRequired。
- 一次早期getPresentationState超时及随后ready=false发生在启动准备中，最终复核ready=true。日志显示本次Qt上下文/资源准备约27秒，记录为既有启动性能待排查，不把本次移除重签机制宣称为启动性能修复。
- 新HAP SHA256：`313a142c813bafb0873e29a02dcb21f2329f868390f537009282c543bcf36df1`；产物审计确认原主初始化3处检查、子进程门禁和平台28个运行内容节仍匹配。
- 正式新协议发布后，需要真机核对：隐私声明单独变更、用户协议单独变更、多份用户协议、冷启动/后台返回/持续前台、取消后重试、查询暂时失败及离线后恢复。记录系统实际下发时机，不承诺刚修改网页正文就自动重签。
- “不需要重新授权”配置下平台如何回填协议版本/结果仍需真机核对；不猜测版本迁移规则，不为跳过核验而放开旧版本。应用侧没有新增主动重签判定/弹窗，但既有授权核验仍保持失败不放行。
- 若未来引入其他持续运行的个人信息业务，也必须接入适当的权限和同意核验，不能用系统负责弹窗作为省略业务授权检查的理由。
