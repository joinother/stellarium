# Seestar S50 Pro 接入与观测图片路线

记录日期：2026-10-01。范围：本轮关于设备接口、合法性、在线巡天及实拍图片替换的讨论。状态：预研与产品方案，用户计划购买设备，尚未完成本项目的 S50 Pro 真机联调。本次不新增应用功能、端口、权限或云服务。

## 核心决策

- 优先使用厂商明确支持的 ASCOM Alpaca，私有接口只作为后续核验候选。
- 复用现有望远镜领域服务、星图标记、观测列表和 CLI，不单独复制一套 Seestar 业务。
- 保留内置资料图片、星表、行星纹理及天空文化插图。实拍是独立的观测资源层，不覆盖原始文件。
- 先完成本机或可信局域网接入；不把控制端口直接公开到互联网，不依赖 ECS 转发图像。
- 设备成像、图像处理、星图展示和科学巡天分别治理，不能把普通照片标记成专业巡天或真实多光谱数据。

## 已核实资料与接口证据

[ZWO 官方产品页](https://us.zwoastro.com/products/seestar-s50-pro)明确支持 ASCOM Alpaca 和第三方天文软件，并列出 50 mm 主镜、2.8°长焦视场、63°广角视场、JPEG/FITS、赤道模式和 128 GB 存储。视场标注为竖向，不能据此猜测完整矩形视场。具体可用控制、相机功能及开启方式仍要按实机固件核验。

[官方手册入口](https://www.zwoastro.com/guides-and-manuals/)已提供 S50 Pro 手册。尚未取得涵盖全部私有指令的厂商正式 SDK；官方产品支持 Alpaca 不等于所有社区命令均获官方支持。

社区 [seestar-api 接口资料](https://github.com/irjudson/seestar-api/blob/main/docs/seestar-api-reference.md)和 [SeeStar-Py 图像协议研究](https://seestarpy.readthedocs.io/en/latest/info/image_stream_protocol.html)是各项目维护者的一手实现记录，但不是 ZWO 的固件兼容承诺：

| 候选接口 | 社区记录 | 本项目决策 |
| --- | --- | --- |
| 设备发现 | UDP 4720 | 用户主动发现；限制选定本地网络，超时结束，不自动后台扫描 |
| 私有控制 | TCP 4700，按行 JSON 请求与应答 | 暂不接入；先核验固件、认证、来源许可及官方替代 |
| 主镜和广角图像 | TCP 4800 / 4804 | 待验证分帧、长度、压缩格式及各型号支持，不按型号名推定可用 |
| 文件传输 | TCP 4801 | 待验证清单、断点、取消、大小限制和校验 |
| 视频 | 4554 / 4555 | 社区资料存在 RTSP/RTMP 标注差异，不能写死协议；需实机确认 |
| Alpaca | HTTP 服务，社区有不同端口记录 | 用发现/用户配置确定端点，不能把 80 当作标准或 S50 Pro 固定端口 |
| 固件操作 | 4350 / 4361 等社区记录 | 不接入、不自动探测、不刷写固件 |

以上是研究候选端口，不是当前应用开放的端口，也不是防火墙放行清单。热点 IP、认证和服务端口存在版本差异，不固化聊天中提及的 IP 或密钥。固件兼容表必须记录型号、固件、接口、功能实测结果和测试日期。

## 合规边界

官方 Alpaca 是首选互操作路线，但仍需遵守设备协议、服务条款、数据和第三方软件许可证；不能凭一个开放端口宣称所有用途均已获授权。

[《计算机软件保护条例》](https://www.cac.gov.cn/2013-02/08/c_126468744.htm)第六条区分软件表达与思想、方法，第十七条涉及学习研究设计思想、原理。这些规定不构成对一切反编译、绕过认证或商业再分发的普遍授权。正式发布前核对当前法规、厂商合同及开源许可，必要时请法律专业人士复核。

实现不得复制或分发 ZWO App 代码、私钥或认证材料，不绕过设备认证、不修改固件、不操作未经授权的设备。开源参考代码在许可证兼容审计完成前不直接复制进仓库；独立实现开放协议时仍保留来源记录。不将本项目宣传为 ZWO 官方应用。

## 在线巡天的两种含义

1. **应用里的在线巡天图层**：HiPS/DSS、GALEX、RASS、2MASS 等是既有天文观测资料服务。S50 Pro 不能替代这些全天天图或空间望远镜波段数据。与[多波段预研](MULTIWAVELENGTH-SKY-RESEARCH-2026-09-08.md)保持分层。
2. **自己拍摄的观测网络**：可规划目标队列、定期重拍、记录结果并显示自己的影像。它是个人观测/小规模时域观测候选，不是已经建成的科学巡天服务。

S50 Pro 对前者的帮助是补充自己拍摄的可见光局部影像，对后者的帮助是提供自动定位与成像的实际设备。Hα/OIII 滤镜属于对应光学通带，不能把照片染色冒充 UV、红外或 X 射线实测。

科学测光或变化检测需另做偏置/暗场/平场、线性数据、时间准确性、WCS、光度标定、误差和质量控制。FITS 扩展名或成像成功本身不代表已满足科学数据标准；不承诺专业全天天区覆盖、发现能力或统一测光精度。

## 内置图片与实拍资源分工

| 对象/资源 | 内置资源的用途 | 实拍资源的用途 |
| --- | --- | --- |
| 行星、月球、太阳 | 继续提供模型、纹理及资料图 | 本次观测记录，不把平面照片直接替换球面纹理 |
| 星系、星云、星团 | 离线科普与识别底图，保留署名和许可 | 单目标实拍、叠加进度、不同日期对照 |
| 恒星和星场 | 星表驱动位置、亮度和选中逻辑 | 局部真实星场，不能反向替代完整星表 |
| 星座和天空文化 | 保留艺术图、连线及文化资料 | 可叠加实拍星场，但不能替代文化插图 |
| 无内置图片的对象 | 清楚提示资料资源缺失 | 有匹配观测时展示，未拍摄时不伪造照片 |

详情页规划“资料图”和“观测实拍”两个来源入口，与现有模型入口统一；实拍仅在存在有效匹配记录时成为可选默认，不破坏离线首屏。星图上的实拍覆盖为用户可切换图层，关闭后恢复内置资料。

叠加到星图之前，必须有可靠 WCS 或解算结果，核验坐标系、历元、尺度、旋转、镜像和畸变；目标名相同不等于图像边界吻合。无解算图片只能进入相册/详情，不自动贴到星图。月球和行星影像还需记录拍摄时刻；不按固定恒星位置做跨日期叠加。

资源索引草案应区分 `resourceKind`（资料/原始观测/处理结果）、`targetId`、拍摄 UTC、曝光、滤镜/通带、设备型号/固件、校准状态、WCS、尺寸、文件大小、SHA-256、来源与许可、派生关系。地点是可选敏感字段，设备序列号不是默认业务标识。原始 FITS 与拉伸后的预览分别保存，不能让图像增强覆盖原始数据。

## 架构与 CLI 草案

```text
ArkUI / CLI / 交互导览 / 观测列表
                ↓
统一望远镜领域服务和能力状态
                ↓
AlpacaAdapter / SeestarAdapter / LX200Adapter / OnStepAdapter
                ↓
用户选择的本地设备或可选的本地 Telescope Bridge

观测文件 → 本地资源索引 → 详情实拍 / 已解算星图覆盖
```

Alpaca 本身是网络协议，不必依赖 Windows ASCOM COM，也不必强制额外部署 Bridge。能直接接入时由鸿蒙客户端访问本地 Alpaca；依赖或性能不满足时再使用可信本地 Bridge。复用[星闪望远镜预研](TELESCOPE-NEARLINK-RESEARCH-2026-09-02.md)和[OnStep 路线](ONSTEP-NEARLINK-PRODUCT-ROADMAP.md)，Seestar 的 Wi-Fi 不能被表述为已支持星闪。

以下都是新增契约草案，未注册、未实现：`discoverTelescopeDevices`、`connectTelescopeDevice`、`getTelescopeCapabilities`、`startObservation`、`stopObservation`、`listObservationImages`、`importObservationImage`、`setObservationImageOverlay`。现有 CLI 原名继续兼容；UI 与 CLI 共享领域状态，不各自发控制指令。

查询反馈需区分连接失败、认证失败、不支持、动作进行中、设备完成、图像准备中、传输失败、解码失败、未解算和无匹配资源；提供事务 ID、取消、超时和错误详情。耗时网络/解码不能阻塞 ArkUI 或星图线程，使用缩略图先行、可见范围加载和缓存预算，不降低屏幕画质。

指向转换必须明确 RA 单位、Dec 符号和 J2000/JNow；真实控制使用设备当前时刻和地点，不把用户的模拟快进时间直接当成设备时钟。Sync、Park、Home 等功能按能力表启用，设备未返回完成不能用动画伪造到位。命令串行化、单主控租约、停止优先；断线重连不自动重放 GoTo 或曝光。

## 本地存储与服务器边界

- 默认本地保存、用户主动导入/连接；不在启动时发现望远镜。
- 不读取手机/Pad 的 SN 或 UDID。设备返回的序列号、MAC、密码默认不记录到日志、不外传。
- 云同步/分享单独授权，支持地点和设备信息脱敏；拍摄照片不默认上传，目标坐标与地理位置分别告知。
- 当前 ECS 仅作为既有官网与资源服务候选，不承载逐帧视频或全量 FITS 自动转发。用户量增长后再按实测文件量、带宽和费用决定对象存储/CDN；不在本任务开通收费服务。
- 官方产品包含远程访问功能，但不等于公开了第三方云端控制 API；厂商云接入需单独取得接口及数据条款，不能拿局域网私有接口当云 API。

## 对话结论修正

- “没有官方接口”的初步说法已由官方 Alpaca 支持信息修正。
- “所有端口已支持 S50 Pro”尚无本项目真机证据；社区列出型号不代表每个接口实测通过。
- 80 不是 Alpaca 固定端口；4554/4555 协议和热点 IP 待确认。
- “有助在线巡天”指个人观测或补充局部影像，不意味着替代 HiPS、多光谱或专业巡天。
- “实拍覆盖层”不是永久替换内置资源，必须经过来源标识与坐标匹配。
- “本地 Bridge”是选项，不是所有鸿蒙客户端的必需依赖。
