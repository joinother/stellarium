# OnStep 星闪控制器：从原型到单板产品路线图

更新：2026-09-09。状态：方案与验收规划，未完成星闪样机联调，未选定采购型号。

## 1. 推荐决策

承接[星闪望远镜控制预研](TELESCOPE-NEARLINK-RESEARCH-2026-09-02.md)，不另建一套望远镜业务。

- 原型：现成 OnStep 兼容控制板 + 星闪开发板，经串口桥接；先确认 Pad 可以与自定义 SSAP 服务互通。
- 首代产品：一块定制 PCB，集成运动主控、星闪芯片/模组、电机驱动、电源与保护。优先单板双主控，不销售裸开发板拼接方案。
- 后续降本：只有量产成本、功耗或体积确有需求，且实时性验证通过后，才评估将 OnStep 移植到单颗星闪 SoC。
- 首代范围：单台赤道仪、单控制端、GoTo、Sync、停止、位置/状态回读；跟踪、Park/Home 按固件实际能力逐项启用。不同时开展无线图传、云控和所有厂商协议。

一块板与一颗芯片是两件事。两颗主控通过 PCB 内部走线通信，无需外露串口线。运动与通信分工有利于隔离故障，但本身不是安全保证，仍要做独立限位、看门狗和失联试验。

## 2. 目标架构

```text
星象仪：ArkUI / CLI / 交互导览
                ↓ 同一望远镜领域服务
        OnStep/LX200 协议适配器
                ↓ 传输适配器
     星闪 SSAP（或已验证的备用通道）
                ↕
┌──────────── 一块定制控制板 ────────────┐
│ 星闪芯片/模组 ↔ 板内UART ↔ OnStep运动主控 │
│                              ↓          │
│ 电源/保护/限位/急停接口     电机驱动器     │
└──────────────────────────────┬──────────┘
                               ↓ 电机与赤道仪
```

运动主控本地生成电机脉冲并执行跟踪，不通过无线链路逐步发送电机脉冲。App 发送高层命令并读取设备反馈；通信确认不等于机械到位，设备报告坐标也不等于编码器测得的实际指向。

## 3. 已有依据与尚未确认的事项

- 既有预研已约定传输/协议/领域状态分离、CLI 统一、能力握手、未知位置不伪装为已到位。本路线沿用这些约束；旧报告中的工程版本、调试地址仅是当时快照。
- OnStepX 官方说明支持串口命令通道及 LX200 兼容控制，可作为桥接基础；具体命令、扩展和坐标历元仍须锁定固件版本逐项验证，不能认为所有 LX200 设备能力相同。
- 海思 Hi3863V100 属于候选芯片系列，不是本项目已经验证的 OnStep 主控或已确认可采购的板型。开发板的原理图、SDK许可、SSAP示例和固件烧录能力必须先取得。
- 2026-09-09 华为 MCP 再次确认：`nearlink-manager` 的 `isNearLinkSupported` 标注6.1.0(23)，新版 `js-apis-nearlink-manager` 标注26.0.0。不得混用两套API；按实际SDK和目标设备编译、运行验证。
- Pad支持星闪外设，不证明应用可以访问本项目自定义服务。尚未完成开发板与MatePad Mini的权限、服务发现、双向读写验证。

## 4. 分阶段路线与验收门

| 阶段 | 实际工作与交付物 | 通过条件/停止条件 |
|---|---|---|
| R0 能力与选型 | 核对Pad系统/SDK/API权限；确认开发板角色、SSAP自定义服务、UART、SDK和供应渠道；确定OnStep版本、赤道仪负载、电机/驱动/电压 | 形成兼容矩阵和候选BOM；资料或权限不明确时不批量采购、不打产品板 |
| R1 无电机通信样机 | Pad↔星闪开发板↔串口回环；实现服务握手、分包、应答、超时和CLI诊断 | 双向数据实测；错误帧、拒绝权限、关无线、重启、退后台可复现；不能只用两块开发板互通代替Pad验收 |
| R2 OnStep桌面样机 | 接OnStep，先查询型号/位置，再做受控低速动作和停止；与有线基线对照 | 查询和命令逐项匹配；没有运动授权不动作；断连不回放旧GoTo，急停与限位通过后才上镜筒 |
| R3 App产品化 | 复用领域服务/CLI，接入能力驱动按钮、位置标记、结构化错误、协议版本和固件兼容表 | 同一操作UI/CLI结果一致；模拟与真机明确区分；无线不可用时有可解释状态，不自动切换并重发运动命令 |
| R4 单板工程样机 | 设计单PCB双主控；先用资料完整的星闪模组减少射频设计变量，完成电源、天线净空、驱动散热、接口保护、烧录/测试点和硬件停止路径 | 负载、温升、电源波动、射频与电机干扰、长期跟踪及故障注入通过；不满足则改板，不进入销售 |
| R5 小批量与商用准备 | 固件版本冻结、生产测试夹具、设备身份/配对、升级恢复、售后诊断、BOM替代料、许可和适用认证评估 | 完成可追溯测试记录和合规评估；确认适用无线/整机要求，不能把模组证书当整机自动合规 |
| R6 可选单主控降本 | 评估定时器、中断、DMA、实时调度和OnStep硬件抽象移植；与双主控相同负载基线比较 | 射频拥塞和升级等压力下仍满足脉冲/跟踪指标，且总成本收益可证明；否则保持双主控 |

阶段编号补充旧预研P0–P4，不替换旧接口定义。当前只完成本路线编写及文档核验，不把任一硬件阶段标记已通过。先执行R0/R1，不先采购整套量产物料。

## 5. 协议、控制与失联规则

1. 固定服务/属性定义和协议版本，区分命令写入、响应、状态通知。遵守平台UUID分配规则，不随意占用标准服务标识。
2. 桥接封装包含会话、请求ID、长度、类型、状态/错误；按协商MTU分片重组，限制帧长、排队长度和超时。不要将任意SSAP片段直接当完整LX200命令。
3. LX200无统一请求ID时，只允许一个待响应事务；按每个命令的实际响应形式解析。运动命令超时后状态为未知，先查询，不盲目重发。
4. 停止命令优先于普通遥测和未发送运动指令；协议队列必须有有界等待。无线停止不能替代本地停止按钮、限位及运动主控看门狗。
5. 手动连续移动采用受限控制租约，释放、超时或失联后本地终止。GoTo与跟踪的失联策略独立设计：原型默认中止GoTo，跟踪是否继续由明确配置和本地安全约束决定，不用“一断线全部切电”掩盖设计问题。
6. 重连建立新会话、读取状态和能力，清空旧运动命令；不同控制端不能同时拥有运动控制权。配对、加密、控制授权需分别验证，不把可发现等同可控制。
7. RA/Dec、历元、单位、地点/时间、半球及机械限位都在协议中明确；超范围目标拒绝，不能靠星图动画证明转向正确。

## 6. CLI、测试与证据

- 复用旧报告的命令契约与当前命令目录，不建立仅UI能用的星闪控制。规划中的命令不得宣传为已实现。
- CLI应能查询能力、连接、队列、设备回传位置、数据年龄、请求结果和错误；动作必须带设备标识并经过同一安全检查。
- 按层提供回环测试、协议模拟器、录制响应回放、硬件在环用例；控制层模拟位置与真机位置加明确来源字段。
- 测量命令/状态延迟P50/P95/P99、停止完成时间、丢包/重连、最大队列、运动脉冲抖动和跟踪误差。具体门槛在R0按赤道仪和负载确定，不照搬星闪宣传延迟作为机械验收指标。
- 初步压力计划：100次连接/断开、8小时桌面运行、24小时工程样机运行；次数和时长是本项目拟定测试，不是认证标准，也不代替机械风险测试。
- 安全验证顺序：无电机回环→无负载电机→低速赤道仪→受控负载；硬件急停随手可达，未明确许可不自动执行无人值守运动测试。

## 7. 成本、隐私与商用边界

- 原型只采购小数量开发板和必要接口器材，已有OnStep板尽量复用；批量报价需包含PCB/贴装、模组、驱动、电源、连接器、外壳、测试、损耗和售后，不能只比较芯片单价。
- 星闪直连不需要云服务器，也不需要读取手机/Pad的SN或UDID。若产品维护需要控制盒自身身份，使用独立设备ID，公开诊断脱敏，不混用用户终端序列号。
- 本轮不修改应用权限、签名、网络访问或正式协议。后续接入按[联网功能清单](../NETWORK-INVENTORY.md)记录本地无线权限、数据和生命周期；时间/观测地点只在功能必要且用户确认时送往指定控制器，不外发公网。
- OnStepX仓库标注GPL-3.0；R5须核对选定代码、修改、分发方式及SDK/模组许可，准备对应源代码和许可履约方案。不能假设板上拆成两颗芯片就自动解决软件许可边界。
- 销售前另行确认产品适用的无线、电磁兼容、电气安全、星闪品牌/认证及销售地区要求，本路线不作“免认证”判断。

## 8. 下一步具体执行清单

1. 锁定Pad实际系统和可用SDK，独立样例验证NearLink API与权限，不改当前发布工程。
2. 收集2–3个支持自定义SSAP与UART的开发板候选，逐个确认资料、供货、烧录和配对方式后再定采购。
3. 确定现有/计划购买的OnStep控制板、赤道仪、电机参数；缺失时先做回环，不猜接线和供电。
4. 冻结最小服务协议及CLI诊断输出，完成R1后再做电机动作。
