### 5.1 月缓存依赖：现状与建议分开

**现状（C）：** loader 的实际 key 是 `[year, month, start, end, language]`，其中 start/end 由设备本地月界生成，所以时区影响体现为边界时间，并没有显式 IANA timezone 字段。每次返回 feed 的 `generatedAt` 都取当前时间，包括缓存命中；它是组装时间，**不能冒充星历计算时间、轨道 epoch 或数据新鲜度**。缓存命中后仍需按真实当前时间重新过滤即将发生的事件。依据：`AstronomySubscriptionFeed.ets:74–124`（完整路径见上表）、`AstronomySubscriptionPolicy.ts:23–52`。

**建议（P，未在本轮实现）：** 保留现有订阅缓存，按实际数据依赖渐进增加 revision，而不是全局加地点后每次定位都清空。

| 层次 | 建议缓存身份/依赖 | 失效原则 |
| --- | --- | --- |
| 全球事件数值时刻 | 规范化时间区间/时标、计算算法版本、星历或事件目录 revision | 输入数据/算法变化或查询区间变化；不因无关地点变化作废 |
| 月份展示 feed | month + timezone（或等价本地月界）+ lang + 上游结果 revision | 月界/DST/语言/上游 revision 变化；若以后缓存已格式化日期文本，还需格式/locale 策略 |
| 当地情况 | 事件身份 + 观测地点/高度/观测星体 + 时间窗 + 地平遮挡/折射等实际策略 + 相关数据 revision | 仅使依赖这些条件的高度、可见性、当地时间等结果失效；不是把全球事件时刻一律重算 |
| 卫星预测 | NORAD + TLE epoch/内容 hash 或 catalog revision + 时间窗 + 地点/高度 + 地平与可见性策略 revision | 轨道、地点、时间或判定策略改变即重新预测；TTL 和请求完成时间不能替代轨道时效判断 |
| 排程元数据 | reminderId/notificationId + 请求指纹 + eventKey/signature/route + journal version | 随系统排程和归属校验维护；不按星历缓存 TTL 丢弃，不把显示缓存当排程事实 |

`harmonyos/ets-source/pages/MainWindowNativeNode.ets:2631–2656` 当前建立订阅 loader，并用经纬度（5 位小数）和高度（整数）构成 observerKey；该接入段没有地平/data revision，也未接入 loader 的 invalidate 调用。**这不是说全球月缓存现在必须加地点**：当地情况/卫星或新数据激活接入时，应有明确 revision 与失效钩子，并验证在途旧请求不能覆盖新结果。不要将构造段观察扩大成“全项目没有失效机制”。

计算与动作也要分开：`MainWindowNativeNode.ets:2685–2693` 的显式“查看星空”会按用户操作改变模拟时间；这不违反只读事件查询不污染模拟状态的要求。测试应分别验证二者，不应禁止合法的查看动作。

### 5.2 提醒 journal：已经实现的恢复，不是新提案

`AstronomyReminderMetadata.ts:32–46` 定义带版本的 journal，保存系统 ID、通知 ID、fingerprint、包名、eventKey、signature、route 和提前量。`AstronomyReminderService.ets:71–101` 用私有 Preferences 持久化并 flush；L126–162 按系统 ID/通知 ID/请求指纹验证归属，预备条目仅在唯一匹配时恢复系统 ID。

`docs/harmonyos/specs/ASTRONOMY-NOTIFICATION-SUBSCRIPTIONS.md:51–67` 记录系统 list 剥离 parameters 的设备现象与对应源码修复。**单次 schedule 成功、list 能恢复 route、点击正确、跨重启恢复、到点触发是不同验收项**；本轮没有复验其中任何设备项，不将主任务的阶段成功扩大成分类订阅和实际送达全部验收。

### 10.2 JD/MJD 纠错：触发时刻与事件时刻分开

S03 L516、528 的值 `2461357.257354899` 是 **JD 数值，不是 MJD**；按 `MJD = JD − 2400000.5` 得到 `61356.757354898844`（末位受浮点表示影响）。本轮用 Node 独立完成数值换算：若将该 JD 按 UTC 时间轴解释，对应 **2026-11-12 18:10:35.463 UTC**，北京时间为 **2026-11-13 02:10:35.463（UTC+08:00）**。因此 L532 详情显示“11 月 13 日”与该 JD **不矛盾**，不应记为日期 bug。

L518 的 `triggerDate` 为 11 月 12 日且没有时区标注；它是提醒触发时刻，URL 的 `date` 则是事件路由中的日期参数，两者本来可以因提前提醒而不同。**日期不同不构成 bug，也不能直接计算真实提前量。** 本次没有确认该来源 JD 的 UT/TT 等时标、`date` 对该类型代表峰值/活动窗口/建议观测时刻中的哪一项，以及 `triggerDate` 的序列化时区；这些仍属于协议语义验证，而非上述 JD/MJD 换算错误或详情跨日错误。卫星样本中 triggerDate 与 date 的显示值相差 5 分钟，与报告的提前量描述一致，但未证明实际送达精度。
