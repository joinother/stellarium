# 桌面服务卡片 UI 与功能调研（2026-10）

## 调研结论

本轮把桌面卡片从“节气提醒牌”改成“观星入口”：卡片只给出一个明确结论、少量证据和一个下一步操作，详细星图、高清图片、3D 模型和实时轨道仍回到应用内完成。天气、联网巡天和实时卫星过境不放进离线卡片，避免把过期数据伪装成实时信息。

参考了华为的[鸿蒙卡片设计规范](https://developer.huawei.com/consumer/cn/doc/design-guides/harmonyos-widget2-0000002731312633)：服务卡片应提取及时、核心、实用的信息，控制信息量和视觉主体；规范建议服务卡片信息不超过约 60%，交互保持克制，并以平和、柔和的动效衔接。参考了[Form Kit 概览](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides-V13/formkit-overview-V13)的卡片形态边界，也参考了[Lunar & Wind Tracker](https://dribbble.com/shots/26159092-Lunar-Wind-Tracker-Minimal-Weather-UI)的低饱和深色、圆形天体视觉和单一焦点，以及[meteoblue Astronomy Seeing Widget](https://business.meteoblue.com/products/plug-play-visuals)对日月升落、月相和夜间观测条件的组织方式。

## 已制作的卡片体系

| 卡片 | 主结论 | 次要信息 | 点击入口 |
| --- | --- | --- | --- |
| 观星手札 | 今晚暗夜观测窗口 | 月相、可见行星、流星雨、卫星目录 | 天象页 / 卫星 |
| 暗夜观测 | 暗夜时长与起止 | 日落、日出、可见行星 | 天象计算 |
| 卫星观测 | 本地卫星目录数量 | TLE/过境说明 | 卫星面板 |
| 月相与升落 | 月相与照明率 | 月出、月落 | 天象计算 |
| 流星雨 | 当前活动流星雨与理论 ZHR | 观测条件提示 | 流星雨面板 |
| 今晚速览 | 暗夜、月相和今晚提示 | 轻量入口 | 星图 |

六种卡片共享同一份版本化本地快照和 `AstronomyCardSurface`，使用卡片实际宽高响应式排版。小尺寸保留“标题—主值—一个按钮”，大尺寸补充两个事实行和更新时间，不把文字压缩到不可读。小卡片不再显示“选择查看过境时间、轨道和数据有效期”这类说明性长文，只保留一个明确入口。

## 视觉改版与首次使用策略

- 取消单一蓝黑面板和通用几何图标，改为按内容使用四组低饱和重点色：月相暖金、卫星薄荷绿、流星淡紫、观星天青；背景保留深色星空层次，以少量星点、轨道线和月相轮廓作为装饰，不依赖远程图片或生成式插画。
- 卡片首次添加直接返回可读的本地快照占位信息，随后异步替换为最近一次星历；不显示转圈等待，不要求用户先打开主应用。已有快照时 `onAddForm` 先返回快照，主应用只负责在用户同意隐私并进入前台后刷新它。
- `getFormSnapshot` 可在不启动 Qt 的情况下读取最近快照；`refreshFormSnapshot` 仍是用户主动触发的前台计算入口。这样卡片可立即使用，同时不在桌面卡片进程里读取 SN、初始化 Qt 或发起公网请求。
- 六个入口都覆盖了静态契约、ArkTS 编译；MatePad 真机覆盖安装后通过 CLI 读取到最新的月相、行星、暗夜、流星雨和卫星字段。桌面系统的“添加卡片/调整尺寸”仍必须在系统桌面管理器逐项检查。

## 暂不放入桌面卡片

- **天气预报：** 需要位置、数据源、缓存时间和联网失败策略；后续单独做“观测条件”卡片，不和本地星历混用。
- **实时卫星过境：** 需要有效 TLE、系统代理提醒或实况窗权益；桌面卡片先展示目录状态，过境倒计时进入应用内详情。
- **多光谱巡天：** HiPS 图层需要网络和许可核验；卡片只展示“已启用波段/缓存状态”，不渲染大图。
- **高清星图和 3D 模型：** 卡片不承担大资源加载，使用点击路由进入应用，避免桌面宿主卡顿和裁切。

## 2026-10-01 再设计：从 Demo 卡片到可长期使用的桌面入口

上一版虽然已经把节气从主视觉移开，但仍然把每种内容套在同一张“图标—大标题—长说明—大按钮”模板里，视觉重心偏中、信息密度不稳定，小尺寸和大尺寸的观感也不一致。本轮按“一个结论、两条证据、一个动作”重新收口：

- 顶部固定为小型栏目眉题、中文标题和本地快照状态，不再用装饰星点填空；用户第一眼先知道卡片是什么、数据是否为本地快照。
- 中段按内容使用不同主视觉：月相用暖金月面，卫星用两层轨道，流星雨用辐射线，今晚天象用观测摘要；图形只承担识别，不伪装成实时照片或真实轨道渲染。
- 主结论使用一个短值，事实行使用两个等宽信息块，避免“地平线/行星/流星雨/卫星”堆成瀑布流；大尺寸才补充一行解释，小尺寸直接隐藏长说明。
- 2*2 小卡片改为“图形 + 一条主值 + 两个短事实 + 一个动作”，2*4/4*4 才显示栏目眉题、更新时间和上下文。卡片按实际宽度和高度响应，不靠固定坐标维持排版。
- CTA 只保留一个主要动作；总览卡片的“卫星”是次要入口，其他卡片不再放第二个无关按钮。卡片点击不启动 Qt、不读取 SN、不主动联网。

本轮的视觉检查采用真实 HAP 编译、MatePad 覆盖安装、卡片快照刷新和系统桌面渲染约束复核；系统桌面上已有卡片的添加/删除/尺寸切换仍必须在桌面卡片管理器逐项确认，静态契约不能代替宿主视觉验收。

## 验收标准

1. 六个 `form_config.json` 条目都能编译，且只有总览卡片为默认卡片。
2. 2*4 与 4*4 下标题、主值、按钮和更新时间不裁切，背景、圆角、边框和按钮颜色一致。
3. 无快照、过期快照、无卫星目录、无活动流星雨都显示可理解状态。
4. 点击总览、卫星、月相、流星雨均进入对应页面；卡片扩展不初始化 Qt、不读取 SN、不访问公网。
5. 应用内打开年历后刷新快照，卡片下一次系统刷新可读到同一份数据。

## 本轮实现与验收补充

- 卡片入口迁移为 `@Entry @ComponentV2`，入口使用 `@Provider` 接收数据，共享表面使用 `@Consumer`；数据字段名与 `updateForm` 的快照键保持一致。该方案依据华为 API 23 起的卡片状态管理 V2 迁移规则，避免卡片宿主继续显示旧的“待计算/待刷新”字段。
- `publishAstronomyCard` 在推送快照后按运行中的卡片去重调用 `reloadForms` 作为宿主缓存刷新提示；`updateForm` 仍是实际数据传输路径。刷新失败保持可见状态，不伪装为实时成功。
- MatePad 真机/桌面宿主回归：`refreshFormSnapshot` 返回 `updatedForms: 2`、`failedForms: 0`，快照包含月相、4 颗可见行星、9.5 小时暗夜、流星雨和 2915 颗本地卫星；卡片按钮路由及卫星详情的文字重叠已修正。
- 代码契约、快照边界、月相路径、时间过期、HAP 构建和离线资源审计均通过；桌面宿主的卡片添加/尺寸选择仍由系统桌面管理器负责，不能用应用内页面替代验收。

## 2026-10-01 实机复验纠偏

- 实际截图和点击验收设备是 `HAD-W32`、设备类型 `2in1` 的 MateBook/PC，不是 MatePad。此前文档中将该设备写成 MatePad，后续以设备属性和截图为准。
- 首次视觉复验发现一个真实的状态管理缺陷：主结论已读取新快照，但事实块通过多参数按值传递的私有 `@Builder`，仍显示“今晚行星”“卫星目录已就绪”等默认值。现改为独立 `@ComponentV2`/`@Param` 事实组件，实机截图已显示真实日出日落、可见行星、卫星数量和快照日期。
- 首次视觉复验还发现 2*4 卡底部被裁切、卫星 4*4 下半部留白过大、月相路径在小尺寸下形状偏移。现已分别通过小尺寸隐藏非必要底栏、增加低干扰轨道示意和使用圆形遮罩修复；不加入伪造的实时轨道或远程图片。
- 通过系统桌面宿主实测：点击总览卡后 `getAstroPanelState` 回读 `tab=5、transitioning=false`；点击卫星卡后 `getSatellitePanelState` 回读 `panel=satellites、matchedCount=2915、loading=false`。这两项不依赖应用内页面截图替代。
