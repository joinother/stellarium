# GT5 与 Watch 5 穿戴端路线

记录日期：2026-10-01。记录本轮穿戴分类、开发者模式、芯片比较、是否独立应用及与望远镜联动的讨论。状态：产品预研；尚未完成 GT5 开发安装、Wear Engine 或 Watch 5 真机验证。

## 设备分类和核验边界

GT5 按轻量级智能穿戴路线研究，Watch 5 按智能穿戴路线研究；两者都属于可穿戴设备，不代表 SDK、应用运行时、系统能力和分发途径相同。华为官方区分低功耗轻量 UI 与更丰富的智能穿戴能力，见[穿戴开发概览](https://developer.huawei.com/consumer/cn/multidevice/wearables/)和[开发入门](https://developer.huawei.com/consumer/cn/multidevice/wearables/get-started/)。具体可用 API 必须匹配用户手表的固件和对应 SDK，不能只按 HarmonyOS 大版本判断。

[GT 系列官方应用说明](https://consumer.huawei.com/cn/support/content/zh-cn15878302/)要求通过运动健康设备页的应用市场安装，并以实际列表为准。未核实 GT5 可直接开启标准 HDC 调试的公开操作；不提供猜测的“连点版本号”步骤，不用 MatePad 调试方法替代穿戴调试资格验证。

本轮没有取得两款产品可比的完整 CPU/GPU 参数或同条件基准；不承诺性能倍数，也不根据网上芯片猜测选架构。Watch 5 的官方产品能力可作为更完整交互的设计依据，不等于本项目已验证能在手表运行 Qt、3D 或完整星表。[Watch 5 官方页面](https://consumer.huawei.com/cn/wearables/watch-5/)

## 同一产品与独立应用

推荐同一“星象仪”产品、同一仓库和共享业务协议；不为了拥有手表功能默认另立一个独立产品。穿戴可执行包仍需按目标 SDK/设备类型单独适配，不代表主 HAP 可原样安装到 GT5。

- GT5 的轻量 UI 单独适配相应运行时，不把现有 Qt/ArkUI 主页面直接复制后宣称兼容。
- Watch 5 采用适合其 SDK 的穿戴 UI，复用领域数据和命令语义，而非强制共用全部界面代码。
- 同工程、同品牌、同包名、同 AppID 和同上架条目是不同层次，不能互相推导。正式决定包名/AppID 前核对 GT5 分发入口、AGC 规则、证书和 Wear Engine 对端映射；不保证两个运行时一定可共用一个发布包。
- 只有设备/分发要求或独立生命周期确有必要时，才创建独立 AppID/包名；异包名接续是否需申请另行复核。
- Wear Engine 用于手机与手表能力通信，不意味着手表端无需安装自定义 UI，也不保证任意 Pad/PC 均可作为其配对主机。[华为 Wear Engine](https://developer.huawei.com/consumer/cn/hms/huawei-wearengine/)

## 功能分层

| 层次 | 规划功能 | 边界 |
| --- | --- | --- |
| GT5 首批 | 卫星过境提醒、目标倒计时、方位/高度、观测清单、振动提示 | 手机上计算和整理数据，手表保存有限离线快照，不初始化完整 Qt 星图 |
| Watch 5 增强 | 目标详情、圆屏方向指引、列表管理、可选独立数据更新 | 本地计算/传感器/网络按性能、SDK及权限实测启用，不默认长时常驻 |
| 设备协同 | 手表查看 S50 Pro/OnStep 当前目标、进度、任务完成提醒 | 由手机主控域同步；不让手表、Pad、PC并发直接发送运动指令 |

方向指引的传感器访问需单独授权及校准。消息包含目标 ID、UTC、观测方位/高度、状态版本和有效期；不默认发送手机 SN/UDID、精确地点或健康数据。Wear Engine 消息链路不作为紧急停止的唯一安全通道；真实设备的停止必须通过可靠且经过验证的主控链路。

## 开发顺序

1. 确认用户 GT5 型号、地区、固件、配对手机系统、开发 SDK 与测试安装渠道，未确认前不采购替代手表。
2. 在现有产品内定义穿戴消息及离线快照，先做模拟器的倒计时/目标页与 CLI 兼容测试。
3. 手机侧接入 Wear Engine，验证连接、拒绝授权、重连、去重、取消订阅和旧快照提示。
4. 按真实业务准备穿戴申请、证书指纹和分发资料，再统一处理最终 Profile；不预申请健康数据或泛化 ACL。
5. GT5 与 Watch 5 分别验收表冠、圆屏文字、字体、多语言、暗色/红光、耗电、提醒可靠性和后台限制。
