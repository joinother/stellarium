# AR 增强天空：传感器融合姿态对准路线（2026-10-14）

> **状态：** 预研设计稿（未实施）
> **关联文档：** `research/AR-ENGINE-PORTAL-ROADMAP-2026-09-23.md`（相机 + AR Engine 门户路线）；本文档是与它互补的另一条路线，两者不互相替代。

---

## 1. 背景与定位

"AR 增强天空"指**不依赖摄像头**的增强体验：用户举起手机对准天空，星图随设备指向实时转动，方位角和高度角与真实天空对齐。它解决的是"这颗星到底在天上哪个方向"的指认问题，而不是"把星星画在相机画面上"的叠加问题。

### 1.1 两条 AR 路线的分工

| 维度 | 传感器增强天空（本文档） | 相机 AR 门户（关联文档） |
| --- | --- | --- |
| 核心输入 | 姿态传感器（旋转矢量/陀螺仪/磁力计/加速度计） | 摄像头画面 + AR Engine 平面/深度/Mesh |
| 渲染背景 | 无背景（纯星图）或纯色渐变 | 相机画面 |
| 设备要求 | 几乎所有手机/平板 | 支持 AR Engine 的部分真机 |
| 隐私成本 | 无相机采集 | 需要相机权限与隐私政策补充 |
| 体验目标 | "指哪看哪"的天空指认 | 地景遮挡、门户裂隙等视觉创意 |

建议产品顺序：**传感器增强天空先行**（全设备可用、零隐私成本），相机 AR 门户在其之上叠加。

### 1.2 为什么单独成路线

现有 AR 预研面板（`ar` 面板、`overlay/portal/depth/sky-only` 四模式）验证的是相机 AR 的渲染顺序与遮罩递进；姿态对准链路（传感器 → 姿态 → 天球指向 → 星图驱动）是一条独立的数据链路，可以先于相机 AR 落地，并且相机 AR 的"相机位姿"最终也要消费同一份指向数据。先把这条链路做对，两条路线共用。

## 2. 姿态数学核心

### 2.1 问题定义

设备屏幕背面向上、摄像头朝向用户视线方向时，星图中心应指向用户正在看的真实天空方向。即需要求解：

```
设备姿态（设备坐标系，由传感器给出）
    → 旋转到当地地平坐标系（东-南-西-北-天顶）
    → 得到屏幕法线（视线方向）的方位角 Az / 高度角 Alt
    → 驱动星图视角到 (Az, Alt)
```

### 2.2 四元数变换链

推荐使用四元数而非欧拉角贯穿全链路，避免万向锁与多次三角插值误差：

1. **传感器姿态四元数** `q_sensor`：设备坐标系相对参考坐标系（旋转矢量传感器给出的即是融合四元数）。
2. **磁北/真北修正** `q_decl`：磁偏角修正，按观测点位置从内置地磁模型计算；无模型数据时可先忽略并在 UI 标注"按磁北对齐"。
3. **屏幕旋转补偿** `q_screen`：设备横竖屏旋转、折叠态展开角度补偿，从窗口/显示 API 读取当前旋转角度生成。
4. **合成指向** `q_sky = q_decl * q_sensor * q_screen`，再转换为地平坐标 (Az, Alt, roll)。

roll（屏幕滚转）决定星图的地平线是否水平，用于让地平线与真实世界对齐，而不是让星图绕视线自转。

### 2.3 指向抽象

实施时定义独立的 `SkyPointing` 抽象（纯 ArkTS 数据类 + 静态变换方法），输入设备姿态四元数，输出天球指向；反向变换（星图当前视角 → 期望设备姿态）用于校准引导 UI。该抽象不依赖 UI 和命令桥，可单独做单元验证。

## 3. 传感器选型与降级链

### 3.1 朝向数据源分层

| 优先级 | 数据源 | 说明 | 降级条件 |
| --- | --- | --- | --- |
| 1 | 旋转矢量传感器（融合陀螺仪+磁力计+加速度计） | 系统融合结果，漂移小，直接给姿态四元数 | 设备不提供 |
| 2 | 方向传感器 | 直接输出方位/俯仰/滚转欧拉角，实现简单但精度较低 | 设备不提供 |
| 3 | 陀螺仪积分 + 磁力计校准 | 自行融合：陀螺仪短期积分，磁力计+加速度计周期性校零 | 仅无磁力计设备 |
| 4 | 手动模式 | 无传感器或全部失败时回退普通星图 + 手动拖动，UI 明确提示"设备不支持姿态对准" | 兜底 |

### 3.2 校准与精度状态

- **磁力计校准**：首次进入增强天空模式时提示用户做"8 字校准"；运行中检测磁强异常（数值超阈、方差突增）时提示"附近有磁干扰，方位可能不准"。
- **漂移检测**：陀螺仪积分路线下，方位漂移超过阈值时自动请求一次磁力计校零并向用户展示精度等级（好/一般/差）。
- **可信度展示**：UI 常驻精度指示（三档），用户可随时查看"当前方位来自哪个数据源"。

## 4. HarmonyOS 能力与实现要点

> 以下 API 名称实施前必须逐个用华为官方文档核对（通过本地 docs 或开发者 MCP），不得凭记忆接入。

- **传感器**：`@kit.SensorServiceKit`（`@ohos.sensor`）。核心关注 `sensor.SensorId` 下的旋转矢量、方向、陀螺仪、磁力计、加速度计条目及各自回调数据结构；订阅用 `sensor.on`，退出 AR 模式必须 `sensor.off` 释放。
- **权限**：加速度计、陀螺仪、磁力计类传感器在 HarmonyOS 上通常无需应用权限；实施时仍须以真机实测为准，并把最终结论写入本文档，不得默认"无权限"。
- **屏幕旋转**：`@ohos.display` / `@ohos.window` 读取当前设备/窗口旋转状态，生成 2.2 节的 `q_screen`；折叠屏还需按折叠姿态补偿。
- **帧率与节流**：传感器回调通常 50～100 Hz，星图视角驱动节流到渲染帧率（如 60 Hz），中间用低通滤波抑制抖动；滤波参数按真机调优，不在代码里写死初值。
- **生命周期**：AR 模式退出、应用切后台、息屏时立即注销传感器监听，避免后台耗电。

## 5. UI 设计

### 5.1 罗盘刻度环

- 屏幕边缘常驻**罗盘刻度环**：显示当前方位角（N/NE/E…+ 度数刻度），随指向平滑滚动，是用户判断"对没对准"的第一反馈。
- 点击刻度环进入**方位快速跳转**：弹出方位选择（八方位 + 任意角度输入），跳转后短暂显示"已对准 XX 方向"。
- 罗盘环颜色/透明度不抢星图视觉焦点，折叠屏展开态可移到外屏边缘。

### 5.2 辅助元素

- **水平仪提示**：设备俯仰接近天顶/天底（>80°）时方位角语义退化，显示"方位在天顶附近不稳定"提示。
- **校准引导**：首次使用的 8 字校准动画引导；磁干扰时的重新校准入口。
- **地平线对齐反馈**：星图地平线与真实地平线对齐程度由 roll 决定，提供"锁定地平线水平"开关（对应现有 `setFlatHorizon` 命令的语义复用）。

## 6. 与现有实现的对接

### 6.1 驱动链路

```text
ArkTS 传感器监听（增强天空模式内）
        │ 四元数融合 + 屏幕旋转补偿 + 磁偏角修正
        ▼
SkyPointing → (Az, Alt, roll)
        │ 节流 + 低通滤波
        ▼
命令桥既有视角命令（panBy / setViewAngles 类）→ C++ 核心 → 星图视角
```

- 复用命令桥 `panBy`（已有"陀螺仪平移 x|y"语义）或补充一个显式的 `setViewDirection(az|alt|roll)` 命令；倾向后者，语义清晰、不受拖动惯性参数干扰。
- 用户手动拖动星图时**暂停**姿态驱动（对应现有 `setViewLock` 语义），松手数秒后询问"重新跟随设备指向"还是"保持手动"。
- 模拟时间/位置与真实观测设置保持一致：增强天空模式强制使用设备真实时间与当前观测地点计算星图，进入模式时校验二者。

### 6.2 不改动核心渲染

姿态驱动只改变视角参数，不触碰投影、地景、图层渲染管线；AR 预研面板（`ar` 面板）的四个模式与增强天空模式互斥进入，UI 上提供两个入口但共享同一份指向数据契约。

### 6.3 缺口登记

- `setViewDirection`（或等价）命令桥命令尚不存在，实施前先在 C++ 侧确认视角控制入口。
- 内置磁偏角模型与观测点地磁数据缺失，第一版先按磁北对齐并标注。
- 传感器回调数据结构、单位与坐标系定义必须以官方文档实测为准。

以上缺口实施时登记到 `KNOWN-ISSUES.md`。

## 7. 隐私与合规边界

- **无相机、无麦克风、无网络**：本路线不申请相机权限，不采集声纹，不上传任何传感器数据；姿态计算全程本地。
- 传感器数据不落盘、不进入卡片/通知快照，退出模式即释放。
- 不在隐私政策中引入新的采集项；仅当后续把传感器数据用于其他用途时才补充声明。
