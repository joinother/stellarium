# 多设备协同与应用接续路线

## 目标

“应用配置”与“应用接力”分成两条能力线：配置备份用于恢复用户偏好，会话接续用于把正在看的星空带到另一台设备。两者不再共用一段可直接复制的原始文本，也不默认传输精确位置或设备身份。

## 当前实现

- **会话接续包**：使用版本化的 `stellarium.collaboration.session` 信封，包含视线、视场、模拟时间、选中目标和必要图层状态。
- **隐私边界**：默认排除精确位置；不会写入 SN、UDID、账号、密码、望远镜主机和端口。需要位置时必须由用户明确选择“包含观测位置”。
- **安全生命周期**：接续包有会话 ID、创建时间和过期时间；目标端先校验类型、版本、大小和有效期，再预览，最后应用。
- **系统接续预留**：已按官方 `onContinue` 数据边界预留同一脱敏信封，但当前 `continuable=false`，不主动声明系统接续能力；这样不会在 Profile、AGC 接续服务和双设备验收完成前引入未验证的系统回调路径。
- **CLI**：支持创建、预览、导出、导入和应用接续包，适合人工操作、自动化和 AI Agent；默认仍可通过剪贴板传递，但展示层只突出摘要，不把原始 JSON 当作主要入口。

## 目标交互

“协同中心”使用三张卡片：

1. **继续当前观测**：恢复本机最近会话，不改变配置。
2. **发送到另一台设备**：选择目标设备或系统分享；显示目标设备、会话摘要、是否包含位置和有效期，确认后发送。
3. **接收观测会话**：从系统接续、分享内容、二维码或本地文件接收；先预览，再应用，失败时保留当前星图。

配置备份仍放在“工具与数据”中，并标注为“完整配置”。配置导入需要确认，因为它可能覆盖插件、语言、图层和用户偏好；会话接续只改变当前观测状态。

## 分阶段推进

### 阶段一：已完成的本地安全垂直切片

- CLI 和 UI 统一使用结构化接续包。
- 剪贴板继续作为基础 SDK 的兜底方式。
- 系统 Ability continuation 暂未开启；当前使用结构化接续包、剪贴板、系统分享或本地文件完成跨设备流转，信封格式保持不变，便于第二阶段接入。

### 阶段二：华为分布式设备发现

- 接入官方设备发现/软总线能力前，先确认 API 版本、Profile 开放能力、AGC“接续服务”、账号和设备授权要求；通过双设备真机验收后再把 `module.json5` 的 `continuable` 改为 `true`。
- 实现源端 `onContinue` 返回 `AGREE`，目标端在 `onCreate/onNewWant` 接收参数，并在 `onWindowStageRestore` 恢复会话；未完成这套生命周期闭环前不启用系统入口。
- 只显示用户主动授权且可用的同账号设备；不扫描公网，不上传到第三方服务器。
- 使用一次性配对令牌和短时有效会话，接收端仍须预览确认。

### 阶段三：协同服务

- 星图主屏可作为控制端，手机/平板/桌面端可作为查看端或遥控端。
- 望远镜控制、脚本播放和视频录制默认只在本机或用户明确配对的局域网内协同；不把望远镜凭据放入接续包。
- 需要云端中转时单独设计账号、加密、日志、删除和备案说明，不把普通 APP 备案等同于云服务授权。

## 不做的事情

- 不把完整 `exportConfig` 当作“应用接力”。
- 不在后台自动广播位置、设备序列号或望远镜地址。
- 不因为已经备案就默认打开公网同步、远程控制或第三方上游数据请求。
