# 卫星凌面与行星表面阴影预研

## 结论

可以实现，而且不需要在 ArkUI 上伪造一个移动黑点。当前 Stellarium 核心已经具备卫星凌面、卫星本体运动、行星球体光照以及卫星在行星表面投下本影和半影的完整渲染链路；鸿蒙移植使用的行星 Shader 与源码一致，后续工作的重点是验证运行时 Uniform、补齐事件入口、CLI、状态探针和连续时间控制。

本功能保持离线，不需要地图、网络、设备标识或新的敏感权限，也不需要改写为 ArkGraphics 3D。现有 Qt、OpenGL ES、EGL 和 XComponent 桥接可以继续承载真实三维渲染。

## 参考录屏拆解

参考录屏 `ScreenRecording_08-29-2026 16-31-27_1.MP4` 展示的是木星卫星凌面过程，主要包含以下行为：

1. 木星保持为有纹理和光照的球体，卫星按真实轨道经过木星前方。
2. 卫星实体和它在木星表面的黑色投影是两个不同对象，位置不应强行重合。
3. 投影随着太阳、卫星和木星的三维几何关系连续移动，并具有半影过渡，不是固定透明度圆形贴片。
4. 时间转轴快速推进时，卫星位置、阴影位置、行星自转纹理和星图都连续更新。
5. 录屏中的可复现时间段约为 2027 年 8 月 2 日 20:25 至 22:42，界面标注为 UTC+08:00，可作为首个视觉回归样例。

## 现有核心能力

### 阴影候选计算

- `src/core/modules/Planet.cpp` 中的 `willCastShadow()` 根据太阳、投影天体和被投影天体的日心黄道位置，判断半影锥是否覆盖行星球体。
- `Planet::getCandidatesForShadow()` 收集当前可能产生阴影的卫星、母天体和同级卫星，并排除自阴影。
- 当前行星 Shader 最多接收 4 个同时投影的天体；这足以覆盖木星四大卫星的常见演示场景。超过 4 个时核心会截断并输出诊断日志。

### 三维数据上传

- `Planet::setCommonShaderUniforms()` 将每个候选卫星转换到被投影行星的本地模型坐标。
- `shadowData` 的每一列包含卫星本地坐标 `xyz` 和真实赤道半径 `w`。
- `shadowCount` 和 `shadowData` 每次绘制行星时更新，因此模拟时间连续变化时不需要 ArkUI 额外驱动一套阴影动画。

### 像素级本影与半影

- `data/shaders/planet.frag` 根据每个像素到太阳与卫星的角半径、角距离计算日面遮挡比例。
- Shader 已区分无遮挡、全本影、环状遮挡和部分半影，并把多个阴影的照度相乘。
- 阴影最终参与行星表面光照，不是覆盖在屏幕上的二维黑圆，因此会自然跟随行星球体、视角、缩放和纹理。
- 环系行星已有独立的环影处理，后续可与卫星投影统一验证，但不应在首版重写这部分逻辑。

### 轨道、纹理和事件资源

- `data/ssystem_major.ini` 已包含 Io、Europa、Ganymede、Callisto 的专用轨道函数、半径和纹理。
- `src/gui/AstroCalcDialog.cpp` 已能区分 `Shadow transit` 与 `Eclipse`，可复用其事件分类思想。
- `scripts/morsels_2.ssc` 和 `scripts/BAS_Jupiter_Moons.ssc` 已提供木星卫星演示与历史事件样例，可作为自动回归输入。

## 鸿蒙渲染路径核验

### 当前架构

鸿蒙端的主星图由 Qt/OpenGL ES 核心绘制，经 EGL 共享与 Native XComponent 提交到 ArkUI 的 `XComponentType.SURFACE`。华为官方 XComponent Native API 支持从 NativeWindow 建立 EGL/OpenGL ES 自定义绘制表面，因此卫星阴影应继续走现有原生渲染管线。

官方参考：

- [使用Node-API接口进行XComponent开发](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/napi-xcomponent-guidelines)

### 已确认的资源一致性

- 源码与鸿蒙生成工程中的 `planet.frag` SHA-1 均为 `3e51e8c0c1480e7aff61862ed4cd48373603bfef`。
- 源码与鸿蒙生成工程中的 `planet.vert` SHA-1 均为 `25f83ede95d4fd09ac1833e2f6b243e258590e6b`。
- 因此当前缺口不是“Shader 没有同步”，而是需要确认目标设备运行时成功链接该 Shader，并实际收到非零 `shadowCount` 和有效 `shadowData`。

## 实现原则

1. 不增加 ArkUI 二维黑点动画，避免阴影与卫星、行星自转、缩放或视角变化不同步。
2. 事件计算、时间导航和三维渲染分层：事件层负责找到时间，渲染层只负责按当前 JD 真实绘制。
3. 时间转轴必须连续改变模拟 JD。快档只提高推进倍率，不通过跳秒、跳分钟或稀疏采样模拟速度。
4. 所有 UI 操作必须同时提供 CLI 契约，便于平板自动回归和后续 AI 控制。
5. 默认不输出逐帧日志；探针仅在显式开启后输出，并做频率限制，避免造成掉帧或业务线程阻塞。

## CLI 与数据契约

建议增加以下命令：

| 命令 | 用途 |
| --- | --- |
| `getSatelliteTransitEvents` | 计算指定行星、卫星和时间范围内的凌面、阴影凌面、掩星与食事件 |
| `gotoSatelliteTransitEvent` | 跳转到事件开始、中点或结束，并可选中母行星、居中和设置建议 FOV |
| `getPlanetShadowState` | 返回当前帧候选卫星、阴影数量、坐标、半径和 Shader 状态 |
| `setSatelliteShadowRendering` | 显式启用或禁用真实卫星阴影，用于设置与 A/B 回归 |
| `previewSatelliteTransit` | 以指定倍率播放事件时间窗，并在结束后恢复原时间倍率 |

建议返回结构：

```json
{
  "planet": "Jupiter",
  "satellite": "Io",
  "eventKind": "shadow-transit",
  "startJD": 2461620.0,
  "midJD": 2461620.02,
  "endJD": 2461620.04,
  "visibleFromObserver": true,
  "shadowCount": 1,
  "shadowRenderingEnabled": true,
  "shaderLinked": true,
  "uniformsValid": true,
  "candidates": [
    {
      "name": "Io",
      "localPosition": [0.0, 0.0, 0.0],
      "equatorialRadiusAU": 0.0
    }
  ]
}
```

示例中的数值只是结构占位，运行时必须返回真实计算值，不能把占位值写入业务逻辑。

## 探针设计

### 原生渲染探针

- 行星名称、当前 JD、当前 FOV 和行星屏幕直径。
- 行星 Shader 是否编译和链接成功。
- `shadowCount`、`shadowData` Uniform Location 是否有效。
- 候选卫星名称、本地模型坐标、半径和候选筛选原因。
- 单次行星绘制耗时、完整帧耗时和最近 1 秒平均 FPS。
- 资源侧记录实际使用的行星与卫星纹理文件，不重新读取或复制资源。

### 日志约束

- 仅在 `setSatelliteShadowProbe=1` 后启用。
- 状态不变时最多每秒输出一次；候选进入、离开或 Shader 异常时立即输出一次。
- 不记录设备 SN、账号、网络标识、精确设备标识或其他个人信息。
- Release 默认关闭，CLI 查询使用结构化返回，不依赖抓取日志文本。

## 产品入口

### 天文计算

在“天文计算”中增加“卫星凌面”页：

- 首次进入默认显示木星与土星的近期事件，不要求用户先在星图中选中天体。
- 可筛选母行星、卫星、凌面、阴影凌面、掩星和食。
- 每个事件显示开始、中点、结束、可见性、建议 FOV、数据来源和本地时间。
- 点击事件先展示预览信息；点击“在星图中查看”才改变模拟时间和视角。

### 星体详情

行星详情可增加“卫星事件”区：

- 当前存在阴影时显示投影卫星和阶段。
- 没有当前事件时显示下一次事件，不使用空白区域。
- 提供“跳到中点”和“连续预览”两个动作。

## 性能与画质

- 不为本功能引入地图式瓦片。阴影是行星 Shader 的逐像素光照结果，瓦片无法改善几何同步，反而会破坏球体连续光照。
- 行星在屏幕上很小时，阴影可能小于一个物理像素，这是正确的分辨率限制；界面应建议缩小 FOV，而不是人为放大阴影。
- 维持最多 4 个实时投影源，避免在移动 GPU 上引入动态循环和不可控分支。
- 时间快进期间继续使用同一帧调度器，禁止 ArkUI 和原生核心各自启动重复绘制定时器。
- 首版目标是在常见 Pad 分辨率下保持与普通行星近景相同的帧率等级，不以降低行星纹理清晰度换取阴影效果。

## 分阶段实施

### 第一阶段：运行时验证

1. 增加 `getPlanetShadowState` 和受控探针。
2. 验证木星近景时 `shadowCount` 能从 0 变为 1 或更多。
3. 验证 Shader Uniform Location 有效，生成工程和 HAP 内 Shader 哈希一致。
4. 增加关闭 ArkUI 面板的 CLI，避免详情卡或时间面板遮挡视觉回归。

### 第二阶段：事件计算

1. 从现有现象计算逻辑抽取卫星事件扫描器。
2. 用粗扫描发现候选区间，再用二分或极值搜索细化接触时刻。
3. 区分卫星实体凌面、阴影凌面、掩星和进入母行星阴影。
4. 增加事件缓存，位置、时间范围或星历源变化后失效。

### 第三阶段：界面与时间预览

1. 增加卫星凌面事件页和详情区入口。
2. 实现事件开始、中点和结束跳转。
3. 使用连续模拟时间预览，结束后恢复用户原时间倍率。
4. 对小视场自动给出建议 FOV，但不强制覆盖用户手动缩放。

### 第四阶段：自动回归

1. 使用录屏中的 2027-08-02 木星事件建立固定回归。
2. 使用 `morsels_2.ssc` 中至少 3 个跨年代样例验证星历稳定性。
3. 覆盖单阴影、双阴影、卫星实体与阴影分离、事件离开和快速时间推进。
4. 平板回归同时采集 CLI 状态、截图、FPS 和受控 Shader 探针。

## 验收标准

- 阴影由真实太阳、卫星和行星几何产生，关闭阴影开关后才消失。
- 卫星实体与阴影可以分离移动，不能强制重合。
- 本影边缘具有连续半影过渡，不出现固定硬边黑圆。
- 连续快进时阴影、卫星、木星纹理和时间显示同步，不跳秒、不闪烁、不残留旧黑点。
- 缩放、拖动、固定位置和打开/关闭面板时阴影仍附着在行星球体表面。
- 无事件时 `shadowCount=0`；进入事件时返回正确卫星；离开后及时回到 0。
- 功能可完全离线运行，并可通过 CLI 完成查询、跳转、播放、停止和诊断。

## 暂不实施

- 不把录屏应用的固定 UI、字体和时间转轴直接照搬到当前应用。
- 不新增在线星历、在线天气或远程事件服务。
- 不为阴影单独制作贴图、视频或逐帧 PNG。
- 不修改 Debug/Release 签名、证书、Provision 或 `build-profile.json5`。
