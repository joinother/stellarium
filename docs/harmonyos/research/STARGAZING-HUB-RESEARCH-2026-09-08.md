# 天文通本机调研与星象仪开发路线

日期：2026-09-08。性质：竞品实机抽查、源码接点核验与规划；不是功能交付或全面质量认证。

## 1. 结论

值得借鉴的核心不是再增加一张工具大全，而是把「何时看 → 去哪看 → 看什么 → 怎么拍 → 记录结果」连成闭环。星象仪继续以 Stellarium 星图为中心，在现有观测工作区、位置、时间和设备工具内完成这条路径；不复制天文通的左侧导航，不恢复已经废弃的 iPad 左栏，也不再增加一套同名插件面板。

建议顺序：先完善离线观测计划与卫星事件卡，再完善摄影设备与三维月面，之后验证本地照片解算，最后按授权与运营准备情况接入天气、地图和实时空间环境。备案完成不等于自动取得第三方数据、地图或照片再分发权。

本轮没有修改应用代码、签名、权限、服务器、DNS 或备案资料，没有导入私人照片、开通会员或改变系统定位授权。

## 4. 产品入口与交互方向

### 4.1 保持一套导航

- 星图：仍是默认核心场景；不强制用天气仪表盘替换开屏。
- 更多 → 观测工作区：今夜、计划、记录。卫星/流星雨的推荐条目只是各自模块的视图，点击进入唯一详情页。
- 位置：收藏地点、地平遮挡与未来地图规划；临时比较地点不直接覆盖当前观测位置。
- 时间：只负责模拟时间及相关设置。多夜观测计划可以调用时间预览，但不复制时间设置。
- 设备/摄影：目镜、相机拼接、曝光/采样计算使用同一设备档案与命令接口。
- 插件管理：启用状态、版本、权限、资源、许可和打开入口；不成为每种功能的第二套设置页。

预览方案应使用只读计算上下文；只有点击「在星图预览」才应用目标、时间和地点，退出可恢复。后台计算不得为了采样不断修改屏幕上正在运行的 Stellarium 状态。

### 4.2 可复用组件与视觉规范

1. 观测结论卡：推荐时段、对象、限制原因、下一步操作；展开才看完整表格。
2. 夜间时间轴：目标高度、太阳高度、月光和天气分轨；固定单位与时区，跨午夜写明次日。缺失天气留空，不以 0 云量代替。
3. 过境卡：宽屏三列显示开始/最高/结束，窄屏改纵向时间线，主要资料不要求横向拖动才能读完。
4. 计算结果卡：数值、单位、假设、适用范围、数据版本；空值区分未知、不适用、加载失败。
5. 三维查看器：保留四周滚动通道、独立全屏入口、复位和退出；物体旋转与观察时刻分开，不把晨昏线画成固定的屏幕遮罩。
6. 图标：复用本项目已获许可的上游/现有图标，统一尺寸、线宽、基线和点击区；不提取天文通图标、地图、月面贴图或插画。
7. 动画：沿用已认可的星体详情分栏组件与方向语义；相邻标签随索引前后移动，层级进退成对，减少动态效果时淡化/取消位移。不得借动画重建整个星图或重载插件。

华为 MCP 核验：`GridRow/GridCol` 支持响应式栅格与断点，适合上述卡片重排；按窗口/容器实际空间布局，不按「手机/Pad」维护两套功能。API 26 的 `ContainerReader` 不直接引入目前 API 24 工程。[官方栅格布局指南](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/arkts-layout-development-grid-layout)

## 5. 离线、联网与资源划分

以下为星象仪建议架构，不是对天文通网络实现的逆向结论。

| 能力 | 离线基线 | 将来的更新/联网部分 | 缺失时反馈 |
|---|---|---|---|
| 月相、日月升落、银河窗口、目标高度 | 本地星历及用户选定位置计算 | 星历版本维护，不需逐次云计算 | 极昼/极夜、无可见窗口均给明确原因 |
| 卫星过境 | 合法内置/导入 TLE 本地传播 | 更新元素与发射信息 | 单星历元、数据年龄、过期/传播失败，不给假精确保证 |
| 流星雨 | 本地目录、极大日期与辐射点 | 年度预报更新、实时流量监测是另一数据源 | 区分历年典型值、当年预测、实时测量 |
| 月面三维、地貌与设备表 | 经许可的本地资源包 | 高清包与档案更新，可选下载 | 索引/文件/解码/就绪分阶段，不静默黑屏 |
| 摄影计算 | 设备参数、FOV、采样、构图与经验估算 | 可选设备档案更新 | 明示曝光模型与假设，不把经验值包装成保证 |
| 照片解算 | 本地图片与适配视场的索引 | 索引包下载；在线解算独立自愿选择 | 超时、星点不足、索引不匹配，不偷偷转云端 |
| 地面方向规划 | 无底图也能显示方位示意/本地合法地景 | 合规地图、DEM、光污染栅格 | 分别标明无底图、无高程、旧版光害，不混成错误位置 |
| 观星天气、云图与雷达 | 只读仍在有效期内的缓存 | 需有授权的供应商更新 | 明示发布时间/有效时间；过期保留参考，不冒充实时 |
| 极光/太阳实时图像 | 历史缓存或本地科普，清楚区分 | 近实时太阳风、空间天气、图像 | 缺数据不等于无极光；不能仅凭 KP 保证可见 |

国内化方案分三层：能本地算的留在客户端；有再分发许可的静态包进对象存储/CDN；天气和地图优先评估正式供应商接口。不要因为源站能打开就批量抓取或镜像。国内普通天气服务是否包含视宁度、透明度、垂直云层和足够时间分辨率，需按字段试用验证，不能宣称天然等价。

现有 ECS 先承担轻量元数据/配置服务；是否能承载某个资源取决于容量和流量预算，并非「资源一律不能上 ECS」。大纹理/地图包优先对象存储与 CDN，不在有限内存服务器堆完整天气模型或重型照片解算服务。本轮不采购、不部署、不改端口。

候选联网功能与外发字段已补入 `NETWORK-INVENTORY.md`，默认不启用。用户自定义来源也要遵守同一下载校验、超时、大小限制与协议白名单，不通过任意 URL 绕过离线模式。服务端代抓必须另做 SSRF 防护；局域网望远镜属于独立显式授权能力，不能混成公共下载源。

## 7. 数据与 CLI 设计约束

以下名称是建议接口，不是已经存在的命令。实施时先比对当前命令目录，优先扩展已有契约并为旧命令保留兼容适配。

| 建议服务职责 | 建议动作 | UI 与 AI 共用反馈 |
|---|---|---|
| 观测计划 | 查询窗口、比较日期、添加目标、预览、恢复、记录完成 | 计划 ID、稳定目标 ID、原因列表、所用时间/位置快照 |
| 环境数据 | 查询能力、刷新、读缓存、取消 | 来源、发布/获取/有效时间、单位、缺失字段、过期标识 |
| 解算任务 | 提交本地文件、查询进度、取消、打开结果 | 任务 ID、阶段、索引版本、匹配数、残差与结果坐标系 |
| 地貌/三维 | 按天体检索地貌、选中地貌、设置观察姿态 | 天体固定坐标、名称语言、数据来源、模型就绪状态 |
| 卡片/提醒 | 列出、订阅、取消、预览状态 | 系统授权状态、下一计划时刻、投递/刷新限制 |

共享请求至少包含 `targetId`、位置引用及坐标系、UTC 时刻、显示时区、设备档案版本；结果补充 `source`、`issuedAt`、`fetchedAt`、`validFrom`、`validUntil`、算法/目录版本。未知值为 null 或具名状态，不能填 0。空间坐标区分 J2000、历元视位置与地平坐标；地图经纬度携带基准，避免底图偏移污染天文计算。

长任务使用可取消的任务队列与稳定结果快照；只读计算不能修改全局观测时间。UI 依赖轻量结果，不持有网络客户端/第二套传播器，不通过反复开关插件刷新面板。通知、脚本、CLI、ArkUI 共用同一规则，语言切换只改显示，不改目标主键。

性能验收建议：固定设备、场景、画质与分辨率对比基线，记录帧耗时 P95/P99、主线程长任务、模型解码耗时和峰值内存；目标是新增后台任务不产生可感知整页冻结。阈值在原型基线上定，不以营销宣称的「秒解析」作为未测承诺。

## 8. 可复用开源技术的选择

### 首选先评估 tetra3，而不是引入整套新天文 App

[ESA tetra3](https://github.com/esa/tetra3) 是 Python 星图解算项目，Apache-2.0；默认数据库针对约 10–30° 视场，不能据此认为覆盖所有窄视场深空照片。适合先在 Mac 做受控图片集原型，再评估算法移植、索引生成与 HarmonyOS arm64 资源开销。不要默认给移动端塞完整 Python 环境；索引所用星表许可需单独核对。

[Astrometry.net](https://github.com/dstndstn/astrometry.net) 可作为更通用的解算/WCS 对照方案，但依赖和索引部署需要额外评估。上游说明整体分发涉及 GPL-3.0-or-later，不能简单当作宽松许可库直接链接进项目；先核对本项目各组件许可兼容性，再决定本地适配或隔离服务。这不意味着建议现在把照片上传公共解算网站。

这两个是候选，不是天文通已使用它们的证据。也不建议为了天气、摄影计算器引入 Celestia；Celestia 继续仅服务独立三维漫游路线。

### 华为能力与后台边界

本轮通过华为开发知识 MCP 读取了栅格布局与卡片刷新文档。Form Kit 支持主动更新、定时/定点更新；配置定时周期以 30 分钟为单位，定时刷新存在每日次数限制，不能把桌面卡片当实时星图循环。优先展示下一事件绝对时间、生成时间及手动更新入口；提醒可靠性按既有代理提醒预研独立审批与测试。[官方卡片刷新指南](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/form-refresh-and-data-interaction)

星象仪应分别建模：天文几何条件、目标类型适配、天气质量、预测可信度。不能给月面观测与暗弱星云完全相同的月光扣分，也不要把不同模型的分数简单平均成「准确率」。每个条件展示原值、来源与缺失项，评分模型版本可通过 CLI 查询。网页可访问不代表存在可商用公开 API；本轮没有找到足以据此接入的完整公开接口与授权文档。

### 11.4 关联光污染网站：有用，但必须核对数据含义

从官网链接进入 [DarkMap](https://www.darkmap.cn/)，其页面公开列出世界夜空亮度图集、VIIRS 夜间灯光、向日葵卫星云图、ECMWF 预报云层及腾讯地图等来源/组件信息。网页还分别说明预报云图不是实况、地面能见度不等于天文透明度。这是很值得复用的「每层讲清含义」设计，不是对数据精度或授权的独立认证。

同页不同位置出现光污染 2024 与 2025 等年份，故本轮不认定其所有图层已统一更新。后续我们的图层卡必须携带数据集名称、版本年份、观测/预报时刻、单位、算法和许可，不能只写「最新」「实时」。不直接采纳网页对暗夜等级、测量精度或适宜观测范围的概括作为科学标准。

资源决策：

- 人工夜空亮度模型、卫星向上辐亮度、现场 SQM 测量是不同量，不能直接换个标签互相替代；基于栅格推导的数值标为估计，保留计算假设。
- 世界图集的原始 DOI `10.5880/GFZ.1.4.2016.001` 是追溯线索；本轮 DOI 抓取失败，未确认原文件许可，不进入自动下载/打包清单。
- 若需要同类离线图层，应向原始数据提供方核对授权后自行生成，或与工具运营方取得明确合作许可；不抓取对方瓦片来建立「国内镜像」。
- 全球小预览与按区域下载可分包；地图、云图、光害、DEM 各自独立版本与缓存失效规则。国内底图和坐标转换需专项验收，不用天文坐标直接套未经确认基准的底图。
