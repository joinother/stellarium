# 默认选中固定与快速缩放的同帧锚定

## 行为约定

- 手动点选、搜索或 CLI 选择新天体时，默认固定其当前屏幕位置，不额外居中。不以详情卡是否展开决定相机行为。
- 取消固定只影响当前选择；选择下一个天体重新默认固定。取消选择后不继续锁定旧目标。
- 双指中心靠近选中天体时固定天体；在其他区域缩放时固定双指对应的天球方向。惯性结束后，选中天体从最终位置继续固定，不拉回手势开始的位置。
- 拖动仍可移动星图并带惯性，结束后固定新的位置。脚本播放和陀螺仪驱动期间继续让出相机控制权；原生 tracking 接口为兼容保留。

## 本次发现与处理

1. OHOS 原先调用桌面 handlePinch，开始时取尚未完成的 getAimFov 而非屏幕当前 FOV；旧缩放动画未取消时，快速接手可能跳向旧终点。改为当前 FOV 作为手势基准，取消旧动画，并直接更新 FOV。
2. 缩放惯性原先在 core.update 之后修改 FOV，投影参数还停留在更新之前。改为惯性先于 update，锚定计算也显式使用当前 FOV。
3. 原 endPinch 在命令队列中、最终缩放投影更新前进行校正和重采样；任意天区缩放的惯性尾段也未持续交接新位置。改为在实际绘制帧校正后才结束手势，尾段持续记录校正后的选择位置。
4. 原锚定通过整数像素 dragView 转成方位角/高度角差，再交给带极点分支的 panView；不是严格的屏幕位置解算。改为在地平坐标下对相机方向和向上向量一起做最短旋转，保留亚像素精度、投影翻转和折射，不改变画质、分辨率。
5. 通过原生 selectedObjectChanged 统一启用固定；详情响应直接带 viewLock，ArkUI 使用原生状态而非等待下一次轮询。采用类型、ID和名称组合标识，避免只用可能为空的英文名区分目标。

## CLI 探针

- `setViewAnchorProbe|true`：开启并清零本轮测量；`false` 关闭。默认关闭。
- `getViewAnchorState`：当前固定状态、目标、锚定比例、pinchMode、是否处于手势/惯性，以及样本数、校正后的最大像素误差、最大校正耗时。
- 指标仅衡量锚定解算，不等价于完整帧率或触摸到显示时延。普通 get 命令不修改相机或清零记录。

## 验证

- 65 项自动检查通过；包括225组执行源码旋转公式的原生数值案例，覆盖150°到0.001°的缩放、四角偏置、反向旋转及相机正交性。
- 先前用 DevEco Node 18 执行其他回归，因缺少 stripTypeScriptTypes 导致3个测试文件无法加载；改用已安装 Homebrew Node 26 后全部通过，未修改测试以掩盖失败。
- 鸿蒙原生构建成功；生成工程仅同步本轮 ArkUI 一行状态处理和已编译原生库，未覆盖其他未提交改动。Default 签名、Release 编译 assembleHap 成功（40.078秒），隐私门禁产物检查通过，覆盖安装至 MatePad Mini，Build 仍为1000052。
- `scripts/test-ohos-screen-anchor-pad.mjs <device> [report.json]` 执行四组语义 CLI 验收：新选中默认固定、4→16→2→32→80倍绝对手势倍率、任意天区缩放后保持最终位置、取消固定/重选/取消选择。首轮通过；M31 从30°到0.375°过程中记录164个校正样本，最大解算残差约0.000009像素；任意天区交接136个样本，最大残差约0.000122像素。以上是投影数值残差，不能当成屏幕或手指实际精度。
- 单靠多次 aa start 发来的 CLI 快速命令，实测末次缩放到 endPinch 的间隔约165ms，超过120ms惯性启动窗口，故两次“惯性必须启动”的实验断言失败。没有为让测试通过而放宽业务阈值；最终脚本只保留其能够可靠覆盖的四组语义验收，惯性另用真实触摸路径测试。
- 实际双指路径：先用 CLI 居中并设置4°，读取目标屏幕位置并截图确认没有UI遮挡，然后用系统 uinput 两指从目标左右50px移到左右180px，耗时220ms。理论松手 FOV 约1.111°，最终0.893864°，确认短惯性确实运行；松手后目标坐标保持，最大解算残差约0.000000015像素，最大校正耗时0.101041ms。前后截图已检查。此处触摸注入专用于手势验收，不用于菜单定位或替代语义导航。
- 测试完关闭探针。原生帧采样仍有约21—42ms的整帧耗时，核心/绘制负载不等于锚定求解成本；不宣称所有天区、卫星、脚本或全部设备已无卡顿。
- 华为 MCP 查阅了 Slider onChange 的 Begin/Moving/End/Click 文档。本轮没有把值变化一概当成用户手势，也未为修锚定而重构无关滑杆。参考：https://developer.huawei.com/consumer/cn/doc/harmonyos-references/ts-basic-components-slider
