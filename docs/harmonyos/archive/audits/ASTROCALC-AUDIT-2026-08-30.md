# 天文计算专项审计（2026-08-30）

## 审计范围

对照 `src/gui/AstroCalcDialog.ui`、`src/gui/AstroCalcDialog.cpp` 和鸿蒙端 `MainWindowNativeNode.ets`，检查天文计算各页的字段、计算入口、状态呈现、异常边界和连续操作行为。此次没有修改签名、隐私、联网或构建配置。

## 当前功能矩阵

## 本轮修复

- 所有简单天文计算请求在发起时清空旧结果并显示“正在计算”，失败时显示可重试错误，成功返回空数组时显示“无结果”，不再把空白误认为卡住。
- 位置、即时 RTS、行星计算、两天体距离、年历、凌日和天象计算增加请求序列；用户快速切换页签、筛选项或刷新时，旧响应会被丢弃。
- 两天体距离曲线不再把“未生成”误显示为“正在计算”；行星实时数据不再把接口失败误显示为持续计算。
- 日心黄道页保留真实计算轨道与天体列表，状态提示只覆盖计算状态，不改变轨道布局逻辑。
- 继续补齐与桌面版表格对应的字段：目录天体位置增加视直径、行星距离和中天；星历增加相位、距离、距日角和视直径，并明确按 J2000 赤经/赤纬输出；行星计算增加相位角和日心距离的显式角度/距离字段。
- 星历结果卡片增加坐标系、观测地点、时区和计算时刻摘要；CSV 导出同步包含新增字段，避免用户无法判断结果对应的观测上下文。

## 仍需排期的精进项

1. **字段对齐**：目录位置、星历和行星计算的核心字段已补齐一轮；仍需补齐恒星时、极距、太阳高度模式和桌面版高级筛选参数。
2. **本地化收口**：将剩余 AstroCalc 硬编码文案迁移到 `I18n.ets`，优先处理页签、筛选器、状态、单位和无结果提示；天体名称继续使用上游 Qt `.qm` 与多语言星名索引。
3. **计算参数快照**：为长任务返回参数摘要，在结果卡片显示“计算时刻、观测地点、时区、范围和采样间隔”，避免用户误把旧结果当成当前参数结果。
4. **导出一致性**：CSV 导出列名、单位和当前语言统一，补充当前观测地点、坐标系和计算时间元数据。
5. **性能分层**：位置表和行星计算保持轻量刷新；可观测性、月相长范围、食相长范围继续使用分片任务，避免阻塞星图帧循环。
6. **自动化回归**：通过 CLI 固定验证“切换参数→旧结果不回写”“空结果可解释”“失败后可刷新”“改变语言后状态文案同步”四类场景，再做平板视觉回归。

## 设计结论

天文计算不应把“没有数据”“正在计算”“计算失败”“当前条件不适用”混成一个空白区域。鸿蒙端后续统一采用：参数区 → 明确的计算按钮/自动刷新策略 → 状态区 → 结果区；所有可点击结果保留跳转到对应模拟时刻的能力。原版桌面端的计算核心和数据字段继续作为事实来源，ArkUI 只负责响应式展示、状态反馈和导出。

## 本轮补齐（2026-08-30）

- 目录天体位置结果增加视直径、行星距离和中天时刻，减少与桌面表格之间的信息落差。
- 星历按桌面版语义明确输出 J2000 赤经/赤纬，并增加相位、距离、距日角和视直径；卡片和 CSV 均显示新增字段。
- 星历结果附带坐标系、观测地点、时区、计算时刻、范围和采样间隔摘要，避免把不同参数产生的结果混淆。
- 行星实时计算增加显式的相位角（度）和日心距离（AU）字段，保留旧的弧度字段供 CLI 兼容。

## 本轮继续精进（2026-08-30）

- 新增 `getAstroCalcContext` 离线上下文命令，统一返回儒略日、本地时间、观测位置、时区、经纬度、海拔、平/视恒星时、时间方程以及太阳/月球当前高度方位；各天文计算页可据此判断结果所对应的观测条件。
- 星历改为真正使用 J2000 赤经/赤纬作为 `ra` / `dec`，同时补充当日坐标、时角、极距、气团质量、是否在地平线以上和日心距离，避免把不同坐标历元混在同一列。
- 详情命令补充极距、时角、J2000 数值坐标、几何地平坐标、地平线状态和角直径数值，供 CLI、脚本和详情卡复用。
- 鸿蒙端在天文计算页显示统一的观测上下文卡片，并在星历结果中显示当日坐标、时角、极距和气团质量；CSV 导出同步增加这些列。

## 复核结论

- 当前最高价值的可见功能缺口已从“数据不完整”转为“桌面高级筛选与完整多语言文案仍需收口”。下一步应优先做筛选条件持久化、单位格式统一和固定输入的 CLI 回归，而不是继续增加重复页面入口。
- 所有新增计算仍只使用 Stellarium 本地核心和已安装星历/星表，不新增运行时联网。

## 本轮调研后的精进（2026-08-30）

- 天文计算面板打开期间，观测上下文每秒刷新一次；离开面板、应用进入后台或页面销毁时停止刷新，避免后台轮询和旧响应覆盖新状态。
- 观测上下文卡片增加太阳/月亮的高度、方位和月面照明摘要，使当前观测条件无需切换到其他页面即可核对。
- 地平位置表补充当日赤经/赤纬、日心距离、视直径和中天时刻；原生桥、ArkTS 类型、界面行和 CSV 导出使用同一组字段。
- 切换到天文计算面板的关闭动作不再触发一次无意义的重计算，减少面板闪动和关闭时的命令堆积。

## 后续优先级

1. **单位与本地化收口**：将 AstroCalc 仍然存在的硬编码标签、单位和状态文案集中到 i18n，并根据距离单位设置统一格式化。
2. **轻重任务分层**：实时位置和上下文保持轻量刷新；星历、可观测性、食相和图表继续采用可取消的分片任务，并显示已完成/总量。
3. **固定回归数据集**：为同一地点、时间和目标保存一组 CLI 基准结果，核对桌面版与鸿蒙端的坐标、事件时刻、单位和空结果语义。
4. **可取消任务接口**：在现有请求序列保护之外增加原生任务取消，以减少用户连续切换页签时无效计算占用。

## 本轮调研与修正（2026-08-30）

- **图表模式编号核对**：界面模式为“高度=0、方位=1、全年=2、月度=3、月距=4、双曲线=5”。CSV 导出此前把 1/2 当成全年/观测窗口，导致方位曲线无法导出且结果可能错配；现已与加载分支统一。
- **导出可追溯性**：CSV 现在除列名外写入观测地点、本地时间、时区、平恒星时、视恒星时和参数快照，用户可以判断文件对应的观测上下文，不会把旧结果当成当前结果。
- **参数快照可读性**：图表页不再显示内部数字模式，改为显示曲线类型、目标、起始时间和范围/采样；今晚可观测、行星计算和年历页也显示当前工作条件。
- **已有状态保护保持不变**：请求序列、长任务进度、空结果、失败和超时状态继续生效，旧异步响应不能覆盖新参数结果。

## 调研结论与打磨顺序

1. **优先级 P0：结果可信度**。先完成单位与多语言收口、CLI 固定数据集和导出字段审计；这是比继续增加新页面更直接的质量提升。
2. **优先级 P1：连续操作体验**。把星历、食相、图表和可观测性统一为可取消分片任务；保留当前“准备中/计算中/无结果/失败/超时”五态，不用空白区域表达状态。
3. **优先级 P1：桌面字段对齐**。继续逐项核对桌面 AstroCalc 的恒星时、极距、太阳高度、月面照明、可见性门槛和筛选器，不在 ArkUI 重写天文算法。
4. **优先级 P2：功能扩展**。在上述结果和交互稳定后，再考虑更复杂的图表交互、批量导出和通知；这些不能以重复入口替代现有页面。

本轮未新增联网、权限、设备标识、签名或构建配置；天文计算仍由本地 Stellarium 核心完成。
