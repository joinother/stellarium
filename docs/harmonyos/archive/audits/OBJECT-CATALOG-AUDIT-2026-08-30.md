# 天体分类与星表审计（2026-08-30）

## 结论

- 内置 `stars_0` 至 `stars_4` 已正常打入离线包，覆盖约 12 等；`stars_5` 至 `stars_8` 是体积很大的可选星表，没有打入当前离线 HAP。因此“星星少”主要是星等上限的产品取舍，不是前五级星表加载失败。
- 原 `getStarCountFull` 使用 `StarMgr::listAllObjects(true)`，它只返回可检索的命名/索引恒星，不能代表星表内的全部恒星；而且同一颗恒星的多个名称会重复计数。现在改为累加已加载 `ZoneArray` 的真实条目数，并用稳定天体 ID 去重命名恒星数，同时返回已加载星表级别数和就绪状态。
- `listObjects StarMgr` 仍然只负责“可检索命名恒星”，接口增加 `listKind=named` 和 `catalogTotal`，避免把可检索条目数误读为星表总量。
- 分类接口实际包含太阳系小天体、卫星、系外行星、深空目录、地质特征和插件目录等约 200 项。此前全部塞进一条横向标签行，用户必须持续横向滑动，部分栏目看起来像不存在；现在核心分类固定展示，扩展分类单独展开并以可滚动网格展示。
- 空分类是有效目录但没有匹配条目，不再被当成加载失败；选中分类后会显示明确的目录数量或空目录状态。分页仍按原生目录返回，未改变离线数据范围。

## 后续边界

- 若需要看到更暗的恒星，必须单独设计可选大星表的存储、安装和容量提示；当前版本保持完全离线，不自动下载。
- “可见恒星”与“可检索恒星”是两种不同指标，界面和 CLI 均应继续保留这两个语义，不能用一个数字替代。
- 新插件注册的分类会进入扩展分类区；插件未加载或目录未准备时，应继续由插件状态接口提供原因，不伪装成空星表。
