# 菜单、插件与脚本统一审计

## 结论

当前用户看到的混乱，主要不是 Stellarium 原插件之间互相调用，而是 ArkUI 曾经为同一能力保留了多个入口：插件页、设置页、图层页、时间页和天文计算页分别暴露了不同的开关。后续采用“一个能力一个入口、插件页只管生命周期”的原则。Pad、手机和未来桌面端共用同一动作 ID、命令和状态模型，响应式布局只改变排列方式。

## 唯一入口表

| 用户任务 | 唯一入口 | 纳入能力 |
| --- | --- | --- |
| 搜索与导航 | Dock「搜索」 | 天体、星座、分类、模糊搜索、导航星快捷定位 |
| 时间 | Dock「时间」 | 时间棘轮、速率、时间导航器、时间方程、恒星时 |
| 位置 | Dock「位置」 | 地球位置、观测星球、地区/城市选择、时区 |
| 图层 | Dock「图层」 | 天空显示、坐标网格、名称样式、星空文化、罗盘和标记 |
| 天文计算 | 更多 > 天体数据与扩展 | 星历、升降、月相、历法、行星位置、可观测性 |
| 观测工作区 | 更多 > 观测工作区 | 观测列表、书签、目镜、角度测量、极轴镜、望远镜 |
| 脚本与自动化 | 更多 > 脚本与自动化 | 播放、暂停、继续、录制、字幕、命令控制、音频控制 |
| 工具与数据 | 更多 > 工具与数据 | 日志、截图、会话和配置导入导出 |
| 系统 | 更多 > 设置 | 隐私、语言、视角、导航、设备、插件启动策略 |

`插件管理`只显示插件名称、作者、许可证、版本、来源、资源依赖、启动加载策略和“打开功能”。它不再复制功能开关；插件功能开关放在上表的唯一任务页。源码插件仍保留，ArkUI 只是改变用户入口，不改变 C++ 模块、脚本命令和兼容性。

## 已发现的重复与处置

- `EquationOfTime`、`TimeNavigator`：归入时间页；插件管理只保留生命周期信息。
- `Observability`、`Calendars`：归入天文计算；观测工作区只管理目标列表，不在进入时自动计算。
- `Sky Cultures`：归入图层；文化切换只更新文化状态，不重建整棵图层树。
- `Oculars`、`AngleMeasure`、`NavStars`、`Satellites`、`MeteorShowers`、`TelescopeControl`：归入观测工作区或天体数据与扩展，不在设置和更多首页重复显示。
- `Tools`、脚本、命令和音频：归入各自工作区；设置页的旧入口只保留兼容旧命令的内部路由，不作为新的可见入口。
- `settings_quick_legacy`、旧 `config` 面板：标记为废弃兼容路由，后续删除前先保证书签、CLI 和旧版本状态迁移。

## 卡顿与闪动治理

1. 进入页面不自动启动重计算；用户点击刷新后才启动任务。
2. 所有会遍历星表或按天采样的任务使用 Qt 主线程可恢复分片，每片不超过一帧预算，并返回 `pending/progress/total`。
3. ArkUI 使用一个在途请求和请求序号，旧结果不得覆盖新页面；状态至少区分“准备中、计算中、成功、无结果、失败、超时”。
4. 面板只保留一层纵向 `Scroll`；横向筛选条和结果表使用明确的独立横向滚动，避免嵌套滚动抢手势。
5. 路由切换只切换状态，不通过变更组件 ID 重建整棵面板树；插件加载请求去重，避免闪屏。
6. 时间控制使用“停止/继续”与“实时”两种不同语义和图标；停止后按钮立即变为继续，实时始终表示回到当前时刻并以正常速率运行。

## 外部网络与离线边界

未备案版本继续不联网。`OnlineQueries`、在线巡天、远程控制、远程同步以及外部星表更新均保持关闭；未来若做国内镜像或替代，先登记域名、权限、端口、认证、外发字段、缓存策略和失效提示，再接入统一资源提供者接口。离线资源缺失必须明确显示“无匹配离线资源”，不能表现为空白或无限等待。

## 脚本、插件与字幕

- 脚本导入先解析 `.ssc` 的名称、作者、许可证、版本、说明和快捷键，所有动作进入同一 CLI 命令白名单；导入不等于执行。
- 插件运行时不接受任意 native 二进制；采用带签名的 manifest、版本兼容范围、资源哈希和能力声明，安装后由应用生命周期加载。
- 字幕、脚本说明、插件元数据、地景介绍和星空文化资料使用统一的结构化资源模型，保留原作者、许可证、来源和致谢，不把长文本压成一行。
- 播放脚本时只保留脚本控制条和字幕层；录制时复用同一命令记录模型，保证录制结果可由 UI、CLI 和 AI 顺序重放。

## 本轮代码动作

- `getObservabilityCalendar` 已改为可恢复分片计算，避免 90 天 × 25 次采样一次性阻塞 Qt 渲染线程。
- 观测页使用长任务轮询显示天数进度，并区分未选中目标和计算失败。
- `getWutTargets` 同样按候选天体分片筛选，返回候选进度，避免恒星/深空目录一次性遍历阻塞面板。
- 观测工作区移除一层嵌套纵向滚动容器。
- 时间停止/继续使用独立的继续图标，避免与“实时”按钮造成误解。

关闭任意子页面时立即清空返回栈，避免重新打开“更多功能”残留上一次路径并显示错误的返回按钮。

后续优先级为：统一生成入口映射和 CLI schema，最后清理旧兼容 Builder。任何删除旧入口的改动都必须先通过 UI 路由、CLI 直达和脚本回归。
