## 代码及资源证据

- `LandscapeOldStyle` 把方位角转换为片号，使用 `int(azimuth / sideAngularWidth)`，再剔除不在批次内的片号。当前分支未将整周边界结果限制到有效范围。
- `StelOpenGL::globalShaderPrefix` 在 GLES 默认声明 mediump float。以 float16 模拟允许的较低精度时，微小负角加 2π 后可能舍入成完整 2π；八片地景会得到片号 8，而有效片号是 0..7。该算术复现与细蓝缝位置吻合，是优先修复候选；尚未通过 GPU 高精度/边界修复前后 A/B 验证确证全部因果。
- guereins 八张图片都是 256×256；检查每张左右边缘下半段 alpha 全为 255。不是原图草地边缘整列透明所致。低分辨率及底面/侧面照片衔接仍可能带来另一种模糊或色差问题。
- 球面全景使用另一套采样路径，横向 GL_REPEAT，并有 textureGrad / mipmap 接缝处理；不能把旧式分片问题扩大为所有地景通病。

## 导入影响与处理方向

`importLandscape` 通过 `LandscapeMgr::installLandscapeFromArchive` 安装 ZIP，校验路径、大小、有效目录等；没有重新拼接照片或修复边缘像素。导入后的渲染器仍由 landscape.ini 的 type 决定。

因此新导入的 old_style 包同样存在这条渲染边界风险，接缝方位还受旋转配置影响；spherical 包不走此片号分支，但照片左右边缘、透明通道、曝光和底部拼接有问题时仍可能有缝。格式有效不能等同于视觉无缝。

后续应优先修正旧式片号首尾归一化、提高关键角度/坐标计算精度，并验证贴图梯度与侧面/底面交界；不能靠模糊、降低分辨率或遮挡东侧掩盖。回归覆盖不同片数、旋转、缩放、投影和底图类型。导入质量检查可提示边缘异常，但不可因自然颜色差异直接拒绝资源。

以上为初轮调查记录。格式依据可参阅 [Stellarium 官方用户指南](https://stellarium.org/files/guide.pdf) 及仓库 `guide/ch_landscapes.tex`。

## 渲染修复（2026-09-08）
