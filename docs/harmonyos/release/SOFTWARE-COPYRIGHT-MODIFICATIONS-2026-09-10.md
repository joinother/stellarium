# 星象仪鸿蒙版本改进说明

用途：软件著作权申请的内容准备与来源核对。拟登记名称为星象仪天文观测软件，版本V1.0.9；追溯候选Build1000053。本文不是权属认定、专项授权书或已经提交的申请。

## 申请方向

按基于Stellarium进行鸿蒙适配与重要功能改进的软件准备申请，重点说明依法享有权利的新增、修改表达。无需为了申请而把整个上游天文引擎重新编写，也无需把不独立运行的文件集合包装成另一款独立软件。

《计算机软件著作权登记办法》第7条明确包括经许可修改后在功能或者性能方面有重要改进的软件。是否含有开源代码与新增独创性表达的著作权问题应分开判断；最高人民法院知识产权法庭的相关案例也区分开源协议义务与独创性贡献的权利基础。具体申请还需如实说明来源、权属和许可。

本轮材料准备与官方许可证明咨询同时推进，不将“尚待确认证明形式”解释成“开源改编不能申请”。也不以增加了任意几行代码、某个文件没有版权头或一个Git提交就认定其达到独创性及登记条件。

## 可用于申请说明的正文草案

本软件在Stellarium天文核心基础上，针对HarmonyOS触屏设备增加原生交互与平台适配，实现统一面板导航和本地命令入口、天体详情展示、独立模型交互、离线资源准备与加载反馈，以及分步骤天文导览及会话恢复。界面层通过桥接接口协调天文核心，结合设备窗口和生命周期维护交互与异步任务状态。

申请材料以依法享有权利的新增及修改表达为重点，保留上游软件和第三方代码、数据、图像的来源与许可证。软件作品说明按修改软件准备，不将Stellarium原天文引擎、Qt及其模板、星表、地景、天空文化资料或通用数学方法描述为个人原创成果。

## 同类案例核查后的办理决定（2026-09-10）

1. **继续按修改软件准备个人申请，不把等待咨询回信作为全部材料工作的前置条件。** 当前项目包含上游核心的实际修改，不为绕过许可材料上传而改选全部原创，也不把尚未独立形成软件的桥接文件虚构为另一款独立产品。
2. **许可证明优先整理为“开源许可及来源说明”。** 材料应包括实际使用版本的Stellarium许可全文、上游明确采用该许可的声明及出处、原署名、修改范围和相应源码提供方式；Qt及其他第三方按各自实际许可核对。GPL是已有的许可依据，不能从上传框名为“授权书”直接推导必须向所有作者另取签字。该材料不冒充上游签发的专项授权书；登记机关是否接受这种证明形式尚未查到可核实的公开个案材料，中文译本及形式要求仍需按官方要求落实。
3. **申请重点为依法享有权利的新增、修改表达。** 用已核对的鸿蒙导航、命令桥、离线管理、详情模型和导览等实现说明改进，不宣称获得原版引擎、资源或全部第三方成果的著作权。软著登记不替代GPL履约。
4. **材料与日期仍须真实。** 法院案例不能替申请人确定完成日或首次发表日。已有源码公开记录，不能直接把应用上架日填成首次发表日；未确认的日期仍不能代造。本轮未上传许可PDF、签署或提交申请。

### 可核实案例与适用边界

- **OfficeTen / OpenWRT二次开发**：（2021）最高法知民终51号。法院公布的案情载明，基于GPLv2的OpenWRT形成的衍生软件于2013年取得登记证书，并涉及底层修改和上层新增代码。裁判区分独创性贡献的著作权与开源协议履行义务。该案直接支持“不因基于GPL软件开发而一概排除自身独创性贡献的权利”；未公开当时登记所交许可附件，也未判定通过socket通信便一定不受GPL约束。[法院公布的案情及裁判要旨](https://ipc.court.gov.cn/zh-cn/news/view-3773.html)
- **VirtualApp**：（2019）粤73知民初207号。判决查明部分记载该软件登记证书及GitHub开源背景，可作为开源软件与登记并存的例子。其涉及原项目权利受让与后续侵权，不能类推为Stellarium二次开发许可附件已获认可；判决中的当事人辩称也不是法院裁判结论。[法院判决全文](https://ipc.court.gov.cn/zh-cn/news/view-1823.html)
- **登记规则**：《计算机软件著作权登记办法》第7条允许经许可修改、功能或性能有重要改进的软件登记；第11条要求相应许可证明。这两项与上述案例共同支持当前办理路线，但不构成本申请必然受理或通过的保证。[国家版权局](https://www.ncac.gov.cn/xxfb/flfg/bmgz/202410/t20241015_869486.html)
