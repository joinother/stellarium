# 星象仪天文观测软件 V1.0.9 设计说明草稿

编制日期：2026-09-08。拟用作软件著作权登记文档的基础稿，尚未排版为正式鉴别材料。权属、名称及最终交存版本以申请人确认结果为准。

## 1. 软件概述

软件面向星空观测辅助和天文学习。用户通过时间、地点与视野控制浏览星空，搜索并选择天体，查看资料及坐标，控制星图图层，并使用分步骤导览认识天体。软件基于 Stellarium 天文核心，增加 HarmonyOS 原生界面和平台适配。

天文模型、数据、真实图像与程序化示意应在界面中区分；本软件不是望远镜硬件安全控制系统，也不将所有模拟图像解释为实际观测照片。本说明不声称天文引擎、第三方数据和全部图像为申请人原创。

## 2. 系统结构

```text
用户触摸、键盘或本地命令
          ↓
ArkUI 界面、面板路由与交互状态
          ↓
本地命令桥及结构化结果
          ↓
Stellarium 天文计算、对象管理与星图渲染

离线资源准备 → 本地文件、资源索引和加载状态
独立详情渲染 → 模型矩阵、光照/示意、后台渲染任务
交互导览状态机 → 命令序列、会话快照、退出恢复
平台生命周期 → 隐私同意、权限、前后台与窗口状态
```

ArkUI 展示与天文核心职责分离。命令返回成功只表示相应阶段成功，不能代替图像解码、真实设备动作或全部后台任务完成的判定。渲染与命令结果通过现有桥接层反馈给界面。

## 3. 主要模块

### 3.1 统一交互界面

以搜索、时间、位置、图层、更多功能作为主入口。手机与宽屏窗口共享业务路由和状态，窗口尺寸影响布局而不是功能语义。面板切换、返回、关闭及动画由统一逻辑协调，避免不同设备分别维护不一致业务路径。

代表实现：`harmonyos/ets-source/pages/MainWindowNativeNode.ets` 中的 `setPanel` 与面板历史处理。该文件内容较多，登记时不能据路径将其中所有实现和引用资源一概算作新增原创。

### 3.2 星空浏览与目标详情

用户拖动、缩放星图，或通过搜索选择目标。核心维护目标身份、视角和模拟时间，界面负责目标卡片、数据栏目及本地资源展示。一次性居中与持续固定目标位置具有不同操作含义。

动态高度、方位、赤道坐标等信息需要与当前时间和观测点一致；静态介绍及资源信息与动态计算分层处理。资料缺失应显示未知或无匹配资源，不用估算值伪装精确测量。本轮不以源码存在代替各天体类别的全量实测。

### 3.3 时间和观测地点

时间模块管理日期、时间速率和暂停/实时等状态。地点模块使用本地地名数据、用户输入的坐标或用户主动调用的系统定位。更改时间与地点后，由天文核心重新计算相应星空；系统定位需遵循运行时权限和隐私流程。

### 3.4 图层、地景与星空文化

用户控制不同星图元素的显示，选择地景和天空文化。文化显示涉及名称、星座线、艺术图与资料，复用的原作者、历史来源和许可证需保留。文化资源及图片不因随软件分发就成为申请人的原创图文作品。

### 3.5 离线资源管理

资源模块准备沙箱文件、资源索引和图像数据，向界面提供准备中、成功、失败或无匹配资源等状态。文件复制、目录处理及解码应避免长时间阻塞前台。没有把源代码中预留的网络接口、国内镜像或未来在线巡天描述为本版本已开放业务。

代表实现：`harmonyos/ets-source/qability/StellariumResourceBootstrap.ets`，以及详情界面的资源状态处理。

### 3.6 独立天体详情示意

详情模型有独立的旋转矩阵，不通过拖动模型改变星图观测视角。部分模型采用本地纹理；程序化类型示意与真实图像分开标识。已有文件包括 `DetailModelGeometry.ets`、`DetailModelRasterizer.ets`、`DetailModelRenderClient.ets` 和 `DetailModelWorker.ets`。

模型渲染任务与界面控制分离，客户端需要处理异步返回和对象切换，避免旧目标结果覆盖新目标。不能将恒星、类星体或星团的类型示意描述为实际观测得到的三维结构。

### 3.7 交互式天文导览

导览内容以目标、视场、标题、讲解和停留时间组成步骤。现有两条路线为太阳系邻居与深空探索。默认手动推进，提供上一站、下一站、暂停、继续、自由观察、返回导览和退出操作；自动前进是可选模式。

播放器状态包括未开始、准备、观察、暂停、自由观察、恢复及错误。执行命令后确认结果，退出时等待在途动作并恢复会话；恢复失败保留错误状态，不能报告已经成功退出。脚本和导览互斥控制相机。

实现依据：`AstronomyGuide.ts`、`StelScriptMgr::beginGuidedSession` 和 `endGuidedSession`。恢复覆盖快照范围内的时间、地点、视角及选择等状态，不覆盖任意文件改写、全部插件内部状态和真实外设动作。

旧脚本保留兼容入口和原作者许可。当前新导览不等于全部上游脚本已完成触屏原生改写；新导览文案也不宣称已完成所有支持语言的翻译。

### 3.8 平台隐私与生命周期

初始化须先取得当前政策下有效的用户同意，再进入后续 Qt 初始化路径。定位、传感器等功能还需相应的用户操作、功能条件和系统权限；隐私同意不是所有权限的替代品。

主入口与子进程路径分别设置门禁，错误或未同意时不以进入星图为目标绕过检查。后台、销毁、异步任务返回时也需维护生命周期边界。本说明仅描述设计，不作监管检测已经全面通过的保证。

## 4. 本地命令接口

现有命令体系连接界面和核心操作。例如天体搜索、视野控制、时间和位置设置，以及导览的 `startGuide`、`guideAction`、`getGuideState`。

异步接口应区分请求已受理和最终结果，通过请求身份及状态查询核对完成情况。相同功能的用户界面与命令接口共享业务实现，减少两套行为的不一致。

CLI 支持范围以实际命令目录及回归为准，不能将“希望一切功能都有 CLI”的目标写成全部未来功能已具备。开发机调试连接与应用运行时公网服务亦须区分。

## 5. 错误处理与数据约束

- 输入无效或目标不存在：返回可解释的失败，不擅自替换目标。
- 资源缺失或解码失败：提供对应状态，不长时间只显示空白占位。
- 导览切站或退出冲突：串行协调，等待或拒绝重入。
- 异步任务过期：避免覆盖后续目标与会话状态。
- 隐私或权限条件不满足：保持功能未启动并告知原因。
- 天文数据时效或精度不足：保留来源和不确定性，不伪造距离、轨道或真实结构。
