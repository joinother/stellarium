# 星象仪 AGC 开放能力申请材料草案

本文件是申请开放能力和重新生成 Profile 时使用的材料底稿。它不代表能力已经通过审核；只有 AGC 显示申请通过、能力可选且新 Profile 生效后，应用才打开对应的正式能力开关。

## 应用与实现边界

- 应用名称：星象仪
- 包名：`com.joinother.skyinstrument`
- 业务类型：天文观测、天象计算与离线星图
- 隐私边界：不读取 SN/UDID；位置、传感器、通知和网络地图均由用户主动触发，并在隐私同意后使用。
- 当前已实现：本地天文通知、下一节气代理提醒基础层、桌面服务卡片、脱敏观测会话接续。
- 当前未宣称已开通：实况窗、优先通知、锁屏/待机/背板卡片、正式接续服务。它们要等 AGC 申请和 Profile 生效。

## 实况窗

### 申请理由

用户主动开始一次卫星过境或重要天象观测后，应用需要在有限时间内展示“即将经过—当前经过—已结束”的状态、目标名称和结束时间。实况窗只服务于已经开始的观测任务，不用于广告、营销或静默推送；任务结束后自动关闭。

### 交互流程

1. 用户在应用内选择卫星或天象并点击“开始观测”。
2. 应用展示目标、开始时间、预计结束时间和本地可见性。
3. 用户主动确认后启动实况窗；中途可在应用内取消。
4. 任务完成、TLE 过期、目标不可见或用户取消时结束并关闭。

### 自验收重点

- 没有用户操作时不创建实况窗。
- 不上传位置、设备标识或账号信息。
- 模拟时间快进不会伪造系统实况窗时间。
- 数据源过期时显示“无法可靠预测”，不继续倒计时。

## 代理提醒

### 申请理由

用户主动订阅下一节气、月相、流星雨峰值或关注卫星过境后，应用需要由系统代理在指定时间提醒用户。提醒只针对用户选择的天文事件，不用于营销；用户可以查看、取消和批量清除提醒。

### 自验收重点

- 首次开启规则前才检查通知授权。
- 未获授权或能力未通过时，规则保持关闭并显示明确原因。
- 代理提醒只使用设备真实时间；不使用星图模拟时间。
- 过期 TLE、改变地点或改变时区后，旧提醒会被取消或重排。

## 锁屏、待机屏保与背板透明卡片

三类卡片共用轻量的天文快照，不在卡片进程初始化 Qt、OpenGL 或完整星图。首期内容为下一节气、月相、今晚天象和用户主动关注的卫星过境；卡片注明生成时间和数据是否过期。

### 卡片交互

- 点击卡片进入应用对应的年历、卫星或观测目标页。
- 卡片只显示必要信息，不展示精确位置、设备标识或账号信息。
- 没有快照时显示“打开应用准备天文数据”，不显示空白。
- 快照失效时显示“数据已过期”，由用户打开应用刷新。

## 接续服务

接续对象是用户主动发起的脱敏观测会话：选中天体、视场、模拟时间、显示方向和可选的概略观测位置。当前已实现版本化会话导出、预览、导入和应用；系统级跨设备接续仍需 AGC 能力审批和双设备验收。

### 明确不传递

`SN`、`UDID`、账号、密码、望远镜地址、望远镜端口和设备凭据永不进入接续包。

## Profile 更新清单

能力申请通过后按以下顺序执行：

1. 在 AGC 确认每个能力的状态为“已通过/可用”。
2. 重新生成与发布证书匹配的 Release Profile。
3. 下载新 Profile，并保存旧 Profile 作为可回退副本。
4. 只在获得批准的能力对应的构建配置中启用开关。
5. 重新构建、安装到 Pad 和 PC/2in1 验收；未通过审核的能力继续保持关闭。

Debug 签名只表示调试证书，不等于“所有开放能力已授权”；能力资格由 AGC 审批和 Profile 决定。
