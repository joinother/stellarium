## 明确不申请

- **优先通知：** AGC 规则限定商务、社交通讯以及重要联系人/@我/加急消息，不符合天文观测提醒场景；先使用获用户授权的普通通知，定时后台提醒须等待代理提醒获批，或另实现用户确认的 Calendar Kit 日历提醒。
- **接续服务：** 当前手机、平板、PC 使用同一应用和同一 APP ID；AGC 已说明同一应用的设备间场景无需为“异包名接续”申请该能力。应用接力先保留本地会话导出/导入，未来若出现独立协同应用再单独申请。
- **ACL：** 当前 ACL 列表没有与星图、观测提醒、卡片或卫星目录匹配的必要权限；不申请泛化的 USB、外部代码、后台常驻、设备信息或浮窗权限。
- **室内高精度定位、位置语义、围栏后台唤醒、蓝牙扫描真实 MAC：** 星图只需要用户授权后的普通位置或手动坐标，望远镜/星闪走本地配对链路，不需要这些能力。
- **推送应用内通话、推送语音播报、RISC、华为钱包、运动健康：** 当前产品没有对应业务或数据处理目的。
- **Wear Engine：** 已纳入后续穿戴路线，但当前尚无穿戴端原型和通信协议，因此暂不提交空泛申请。进入手机/手表消息互通、设备状态或观测提醒原型后，按实际场景申请“设备基础信息”和“穿戴用户状态”等接入权限；不因天文应用而申请健康传感器，除非未来确有明确、合规且获授权的传感器业务。
- **云认证、云存储：** 只有在明确上线账号体系、跨设备云同步或用户文件云端存储后才评估，不为路线图占位而申请。

## 后续申请门槛（官方 MCP 复核，2026-10-01）

穿戴产品的具体分层、GT5 测试渠道、AppID/包名待确认项见[GT5 与 Watch 5 穿戴端路线](../research/WEARABLE-GT5-WATCH5-ROADMAP-2026-10.md)。不因同一产品就假设同一 HAP 可跨两种穿戴运行时安装，也不提前创建独立手表产品。

- **实况窗权益（2026-10-25 更正）：** 已收到场景不符的退回通知，不能按已获调测权益继续推进。NAVIGATION 指步行、骑行、车辆导航。当前官方文档中的 PROGRESS 可另行评估用户主动下载星表或导入资源的真实任务，但须先核对 SDK/API、设备和申请条件，再提交实际场景，不能把卫星过境换名重报。依据：[Live View Kit 简介](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/liveview-introduction)。
- **锁屏沉浸实况窗：** 与本轮的普通锁屏卡片不同。若做卫星倒计时的大型动态锁屏展示，还需核对并申请相应实况窗及锁屏沉浸实况窗权益，不能凭普通锁屏卡片审批直接启用。依据：[锁屏沉浸实况窗](https://developer.huawei.com/consumer/cn/doc/best-practices/bpta-lock-screen-immersive-live-window)。
- **星闪望远镜、蓝牙、AR 相机、协同设备：** 接入时按实际 API 声明并在业务触发时请求对应普通权限。`ACCESS_NEARLINK` 为 normal/user_grant，不因使用星闪就必须申请受限 ACL；同时核对 API 与设备支持，不能因权限名称已存在就承诺 API 23 设备拥有所有星闪接口。依据：[用户授权权限列表](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/permissions-for-all-user)。
- **受限 ACL：** 仅在确定使用的 API 明确需要受限权限且开放场景匹配时提出申请；例如未来若采用外设 DDK 驱动服务，需要按具体驱动和权限字段另做审计。普通联网、摄像头、蓝牙/星闪配对不等于需要跨级 ACL。依据：[应用权限管控概述](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/app-permission-mgmt-overview)。

## 联网数据与开放能力边界

TLE、星表、HiPS/多光谱、天气、ADS-B、SIMBAD、MPC、照片解算和望远镜局域网控制不通过“多申请 AGC 权限”解决：它们分别受 `INTERNET`、数据源许可、用户主动触发、隐私告知、超时/缓存回退、服务器容量和设备连接范围约束。备案不会自动授予这些数据的再分发权，也不会自动授予 Profile 能力。

## Profile 收敛策略

当前保留已有历史 Profile，并将 `skyinstrument-release-capabilities-2026-10` 作为本轮能力审批期间的唯一候选发布 Profile。它当前不包含待审批能力，不能被视为代理提醒、实况窗或卡片正式权益已经生效。

在本轮计划交付的能力实际获批并启用前：

1. 不再创建、下载或替换 Profile。
2. 不改动证书、签名、JSON5 或构建脚本。
3. 继续用现有 Debug/Release 配置验证离线预览、参数校验和失败回退。

以实际获批且启用的交付集合做一次收口，不等待场景不符的实况窗无限期阻塞其他能力。按官方要求重新生成匹配的 Debug 和 Release Profile 并使用手动签名；优先更新候选 Profile，平台不支持时再新建一组明确命名的配置。记录证书、包名与能力映射，未被任何构建引用的历史 Profile 仅标记待清理。退回和补材料本身不需要生成 Profile；清理前核对已发布版本和 CI/DevEco 配置。
