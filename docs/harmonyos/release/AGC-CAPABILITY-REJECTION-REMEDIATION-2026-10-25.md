# 星象仪：三项开放能力退回整改

核对日期：2026-10-25。APP ID：6917612145896121937。
审核结果来自开发者提供的 AGC 通知；规则通过华为官方文档 MCP 核对。本文为整改方案与申请草稿，本次没有重新提交申请、修改签名或生成 Profile，也没有完成新增界面的设备验收。

## 1. 审核结果与处理

| 能力 | 退回日期和原因 | 处理 |
| --- | --- | --- |
| 实况窗 | 10-09：天文观测不在开放场景内 | 撤回内部路线中的“观测导航适配 NAVIGATION”判断，不重复提交同一场景 |
| 代理提醒 | 10-08：缺少应用内用户设置提醒的场景截图 | 优先完善真实设置流程、准备功能截图及应用分类截图，再重申 |
| 锁屏卡片 | 10-08：只有 1×1、1×2，信息与刷新受限，现有业务描述不匹配 | 独立设计小尺寸摘要卡，去除轨迹、实时进度及秒级倒计时承诺 |

这是具体能力的退回，不能据此推断应用整体下架、SN 整改失败或其他能力失效。

## 2. 源码核对结果

- `harmonyos/ets-source/qability/AstronomyReminderService.ets` 已封装日历型提醒的发布、查询和取消，检查通知授权并返回受限权限错误；存在接口不等于已获后台提醒权益。
- `harmonyos/ets-source/capability/NotificationController.ets` 与 `panels/settings/NotificationSection.ets` 的用户入口为“订阅下一节气提醒”和“清除全部提醒”。当前没有完整的事件时刻确认、提前量选择和逐条管理界面；不应以 CLI 可传任意事件代替用户设置流程截图。
- `harmonyos/resources/base/profile/form_config.json` 现有六种桌面卡片，尺寸为 2×2、2×4、4×4；没有 1×1、1×2，也没有锁屏要求的 renderingMode 配置。不能把桌面效果图当作锁屏实现证明。

## 3. 代理提醒：先让申请材料与实际功能一致

最小闭环先覆盖节气日历提醒，随后扩展卫星过境、流星雨和月相；未完成的事件类型不写成已具备。

实施和取证要求：

1. 展示事件名称、真实本地日期时间及提醒时刻，用户主动确认。若提供提前量，确认页同步显示计算后的时刻。
2. 展示已安排列表，支持逐条取消；修改时刻时可靠替换旧提醒并防止重复提交。未获权益或通知授权失败时，明确显示未安排成功。
3. 附实际应用“事件选择→时刻确认→管理/取消”的截图，以及 AGC“应用上架→应用信息”的应用分类截图。核对分类符合官方开放范围，不能为了申请伪报分类。
4. 获批前可提交真实的设置界面与明确标注的设计方案，不伪造系统提醒成功截图。获批后补测后台、进程结束、取消、时区变化、通知关闭和重启行为，分别记录系统实际表现。
5. API 25 及以下每应用最多 30 条有效提醒；API 26 起为 64 条。兼容 API 23 的路径必须处理 30 条限制，并以系统有效提醒列表为准，不能仅按“时刻已过”自行认定配额释放。

申请原因草稿（在上述节气设置流程完成并截图后使用）：

> 星象仪提供用户主动设置的节气日历提醒。用户在应用内查看节气日期和提醒时刻，确认添加后由系统在指定时间提醒，并可在提醒列表中取消。申请代理提醒用于应用退至后台或进程结束后的定时提醒，不用于营销。附件包含实际设置流程、取消入口及 AGC 应用分类截图。仅在用户授权通知后发布提醒，不读取或上传 SN、UDID。

获批前的替代路线是通过 Calendar Kit 在用户确认后添加系统日历事件及提醒，需另实现与验收；普通应用内计时器不能承诺进程结束后仍提醒。观测坐标如参与卫星计算，隐私说明应区分本地计算与联网传输，不笼统声明完全不处理位置。

## 4. 锁屏卡片：独立小尺寸设计

| 尺寸 | 信息层级 | 点击行为 | 更新策略 |
| --- | --- | --- | --- |
| 1×1 月相 | 月相轮廓图标、简短月相名、日期 | 月相详情 | 缓存计算结果，按日更新，不持续启动星图引擎 |
| 1×2 下次天象 | 短事件名、绝对日期和本地时刻 | 对应事件详情 | 用户更换事件时更新，遵循系统刷新限制；过期数据不冒充“下一次” |

采用系统单色/自适应配色，重点是图标与时间的可读性；不搬入桌面卡片的大图、长说明、进度条或多按钮。不承诺逐秒刷新。无有效事件时显示明确空态，缓存日期/时区失效时不继续展示为实时计算结果。

配置需包含 `renderingMode: singleColor` 或 `autoColor`，以及 `supportDimensions` 中的 `1*1`/`1*2`；实际字段和布局按当前 SDK 编译验证。独立处理添加、快照读取、更新和删除生命周期，不能只改尺寸字符串。

用户通过手机/Pad 的锁屏编辑界面主动添加或移除；应用不能自动占用锁屏位置。官方支持设备为 Phone、Tablet，MateBook 桌面卡片测试不构成锁屏验收。

申请原因草稿（不足 256 字，附尺寸设计及实际实现证据后使用）：

> 星象仪申请锁屏卡片，用于用户在锁屏编辑界面主动添加的天象摘要。1×1 显示月相图标、月相名称和日期；1×2 显示用户选择的下一天象名称、日期及本地时刻。采用单色或自适应配色与缓存数据，遵循系统刷新限制，不展示实时进度、轨迹或秒级倒计时。点击进入对应详情，用户可自行移除；不展示精确位置和设备标识。附件提供两种尺寸的设计与功能说明。

提交材料包含两种尺寸的设计图、信息字段、刷新/过期策略、添加删除流程；原型和真实系统截图分别标注。权限未获批时如无法系统添加，说明限制，不伪装已验收。

## 5. 实况窗：停止错误分类，评估真正匹配的任务

官方 NAVIGATION 适用于步行、骑行、车辆导航。卫星跟踪、流星雨观测即使有开始和结束时间，也不能因此归入该场景。也不能改称 TIMER 绕过范围限制。

当前官方文档列出 PROGRESS：用户手动开启的文件上传/下载、资源导入/导出进度。可进一步评估星表、地景或离线多光谱资源包的用户主动任务；自动后台资源更新不属于该适用范围。必须先核对 PROGRESS 在所用 SDK、目标 API 和设备上的支持情况，完成真实任务进度、取消、失败及结束行为后再另行申请，不保证获批，也不假设 API 23 已支持。

原卫星/流星雨业务保留应用内进度展示；后台定时提醒走获批的代理提醒或另行接入的系统日历。小锁屏摘要卡不能替代实况窗的高频更新。

## 6. 交付与 Profile 顺序

先补代理提醒的实际界面与截图，再完成锁屏两尺寸设计/实现及材料。PROGRESS 作为独立后续评估，不阻塞前两项。

审核通过并在 AGC 启用、保存能力后，再为实际交付集合集中生成匹配的 Debug/Release Profile，使用手动签名验收。Debug 签名不自动拥有全部受限能力。退回或重新上传材料不需要生成新的 Profile；保留正在使用的历史配置，核对引用后再清理。
