## Stellarium HarmonyOS — 触摸路由修复 (touchfix4) ✅ 验证通过

**核心故障**：ArkUI 覆盖层"点不了"（交接文档最紧急项）。
**根因**：Qt 的 NODE 型 XComponent（qohos 窗口）在 native 层独吞所有触摸，ArkUI 覆盖层必须靠"顶层 Stack 设 HitTestMode.Block + 挂 .onTouch 分发器 (Arch A)"才能抢到事件；且侧栏原用 Flex 自动排版，与 handleUiTap 坐标公式不匹配 → 点错面板。

**已落地修改**（`stellarium-src/build/libstellarium-harmonyos/entry/src/main/ets/pages/MainWindowNativeNode.ets`）：
- 顶层 harmonyShell Stack 恢复 `HitTestMode.Block` + `.onTouch(handleOverlayTouch)`（Arch A 分发器）。
- expandedShell / verticalRail 由 Column 改 Stack，按钮按 `railTop + idx*104` 绝对定位，与公式严丝合缝。
- 新增 `railTop()`=`max(0,skyHeight-724)+30`、`railHeight()`=`actions.length*104`。
- `isUiPoint`/`handleUiTap` 的 x 判定范围改为 `0..64`；compact `itemWidth`=`skyWidth*0.92/(actions.length-1)`。
- 坐标换算：`touchWindowX/Y = windowX??screenX??x`；uitest 布局像素 = vp×密度(2)，故 windowX = uitest_x/2。

**验证结果（模拟器 MatePad Pro 13 横屏 1440x960 vp）**：

### 实测中又发现并修复 3 个真 bug（本轮关键）

**Bug A — 面板裁剪**：`floatingPanel` 的 `maxHeight:430` 太小，位置面板「应用」按钮被裁到可视区外点不到。修复：放大 `maxHeight` 到 660（floating）/ 560（compact）。✅ 修复后「应用」按钮在 (2276,1424) 可见无需滚动。

**Bug B — 头部坐标不刷新（最隐蔽）**：点「应用」后状态变"已同步到星图"（原生 ok=true），但顶部「位置/坐标/海拔」仍 `--`。
- 用 `hilog` 埋点证实：`setLocation` 与 `refreshState` 都**正确把 locationText/coordinateText/altitudeText 设成了真实值**（日志 `refreshState END locationText=[Beijing · Earth] coord=[39.90°N / 116.41°E] alt=[44 m]`），但 UI 仍渲染 `--`。
- 根因：`infoRow(label, value)` 是 `@Builder`，`value` 作为 **builder 参数**传入 `Text(value)`；ArkUI 对 builder 参数的响应式刷新不生效（参数按值快照），头部永远停在初始 `--`。而同样用 `Text(this.x)` **直接绑定**的状态文本（"已选择"→"已同步"）能正常刷新。
- 修复：把位置面板里这三行从 `this.infoRow('位置', this.locationText)` 改为**直接 `Row/Text(this.locationText)` 内联绑定**（与能正常刷新的状态文本同一写法）。✅ 实测头部稳定显示 `Beijing · Earth / 39.90°N / 116.41°E / 44 m`，走「北京」按钮或地图选点+「应用」均刷新。

**Bug C — 三级联动点不动**：「按地区选」点大洲后国家列不填充。
- `hilog` 证实 `selectContinent('亚洲')` 被调用且 `hierRegions()` 返回 79 个国家——数据层正常，是**渲染层**没画出来。
- 根因：`hierColumn(items: Array<string>, ...)` 把动态列表当 **builder 参数**传入，`ForEach(items,...)` 不随 `@State` 变化重渲染（与 Bug B 同源）。
- 修复：`hierColumn` 改为收 `kind: 'continent'|'region'|'city'`，内部用 `if(kind===...)` 直接 `ForEach(this.hierRegions(), ...)` 读取响应式列表（注意：`@Builder` 体内不允许 `let items=...` 普通语句，只能用 UI 组件/控制流语法，否则编译报错 `Only UI component syntax can be written here`）。✅ 实测：洲(10)→国家(79)→城市(迪拜下几十个) 三级全部联动；点城市 Abu Dhabi → 应用 → 头部显示 `Abu Dhabi · Earth / 24.45°N / 54.40°E / 6 m`。

### 本轮关键经验（可复用）
- **ArkUI @Builder 参数响应式陷阱**：凡把 `@State` 数组/字符串作为 `@Builder` 参数传给 `Text`/`ForEach`/`ForEach` 等，**都不会随 @State 变化重渲染**。必须改为在 builder 内部直接 `this.xxx()` 读取，或用 `@Link/@Prop`。`infoRow` 与 `hierColumn` 都踩了这个坑。
- **验证方式**：`uitest dumpLayout -p /data/local/tmp/x.json -b org.qtproject.example.stellarium -m false -i` + `hdc file recv` 回本地 + Python 解析 `attributes.text/bounds`（第 3 组 `[x,y]` 为中心坐标，= vp×密度2）；点击用 `uitest uiInput click <x> <y>`（位置参数非 `-x -y`）；坐标随面板高度变化会下移（面板变高后洲按钮从 y494 变 y902），**每次点前必须重新 dump 拿真实坐标**。
- **@Builder 体内只能写 UI 语法**：`let x = ...` 这类赋值会编译失败。
