# 面板、插件与脚本架构规划

## 目标

Pad、手机和后续桌面端只保留一套动作语义，响应式布局只改变排列方式，不再为不同设备维护不同功能入口。主 Dock 负责高频核心操作；“更多功能”负责进入工作区，不直接重复列出所有插件按钮。

## 统一归属

| 领域 | 唯一入口 | 内容边界 |
|---|---|---|
| 搜索 | Dock「搜索」 | 天体、星座、分类、模糊搜索和导航 |
| 时间 | Dock「时间」 | 时间轴、时间速度、时间导航器和时间方程摘要 |
| 位置 | Dock「位置」 | 观测位置、地图和时区 |
| 图层 | Dock「图层」 | 天空显示、星空文化、网格和标记 |
| 天文计算 | 更多 > 天体数据与扩展 | 升降、星历、历法、月相和可观测分析 |
| 观测工作区 | 更多 > 观测工作区 | 观测列表、书签、目镜、角度测量、导航星、极轴镜和望远镜 |
| 天体数据与扩展 | 更多 > 天体数据与扩展 | 卫星、流星雨、三维地景、星表和插件管理入口 |
| 自动化 | 更多 > 脚本与自动化 | 脚本播放/录制、命令控制和音频控制 |
| 工具 | 更多 > 工具与数据 | 截图、配置导入导出、会话和运行日志 |
| 系统 | 更多 > 设置 | 隐私、语言、视角、导航、插件启动策略和设备设置 |

插件管理只负责模块元数据、作者/许可证、启动时加载策略和“打开功能”跳转；不再复制一套插件开关。插件的即时显示或模拟参数必须留在对应的唯一功能面板中。时间方程、时间导航器、历法、可观测分析等虽然在 Stellarium 中是插件实现，但在本端按用户任务归入时间或天文计算，插件页只保留生命周期管理。

## 导航规则

- 从 Dock、快捷键或 CLI 直达页面时清空导航栈。
- 从“更多功能”进入工作区或具体功能时压入当前页面，并在标题栏显示“返回上一级”。
- 返回只恢复上一级页面，不重新发起无关计算，不改变星图选中、视角和锚定状态。
- 关闭按钮关闭整个面板；它不等同于返回，避免用户在多级页面中迷路。
- 详情卡、极轴镜和系统弹层属于独立浮层，不混入工作区路由。

## 当前插件盘点

### 已有原生端面板

`Oculars`、`AngleMeasure`、`NavStars`、`Satellites`、`MeteorShowers`、`Scenery3d`、`TelescopeControl`、`MosaicCamera`、`ArchaeoLines`、`PointerCoordinates` 和 `TextUserInterface` 已有对应桥接或面板。它们现在从工作区进入，避免在“更多功能”、设置和图层同时出现相同入口。

### 已归并到核心任务页

`EquationOfTime` 归入时间，`TimeNavigator` 归入时间，`Observability` 与 `Calendars` 归入天文计算，`Sky Cultures` 归入图层。归并只改变 ArkUI 入口，不改变 C++ 插件模块或脚本兼容性。

### 资源型或暂不开放的模块

`Exoplanets`、`Pulsars`、`Quasars`、`Novae`、`Supernovae` 和 `NebulaTextures` 先作为搜索分类/显示扩展；`OnlineQueries`、在线巡天和远程网页功能保持离线构建中不可用。`RemoteControl`、`RemoteSync` 只允许在明确开启本机或局域网控制后接入，并遵守 `NETWORK-INVENTORY.md` 的端口、认证和外发字段记录。

## 卡顿与状态策略

- 进入观测列表不自动计算可观测目标；用户点击“刷新”才启动计算，并显示准备中、成功、无结果或失败状态。
- 插件首次载入只允许一个请求在途；页面切换不重复 `loadPlugin`，也不销毁整个面板树。
- 路由切换复用 Scroll 节点，不通过更换 id 强制重建内容，减少闪烁和滚动位置丢失。
- 长计算必须使用异步命令和进度状态，不能在 ArkUI 点击回调中同步等待原生计算。

## 脚本与插件导入方向

脚本可以先做离线导入：解析 `.ssc`、读取 `Name/Author/License/Version/Description`，检查命令是否在本端白名单，拒绝路径穿越、未知文件写入和网络命令，并以统一字幕/元数据模型展示。插件不能像脚本一样在运行时直接加载任意 native 二进制；后续应采用“签名的插件包 + manifest + 版本兼容范围 + 资源校验 + 沙箱能力声明”的发行流程，安装后由应用重启加载。插件包的作者、许可证、来源和 acknowledgements 必须原样保留。

## 后续阶段

1. 完成工作区路由回归，覆盖 Dock、Pad、手机和 CLI 直达。
2. 将所有插件按钮映射表生成化，避免新增插件时手工散落入口。
3. 建立脚本字幕、插件元数据和地景/星空文化介绍的统一资源索引。
4. 增加导入包校验、兼容性报告和离线资源缺失提示。
5. 对需要联网的模块逐项完成镜像或国内替代评估，未验证前保持关闭。

## 本轮收口规则（2026-08-29）

- “更多功能”只负责进入三个工作区、工具与数据、设置和帮助；工作区下的功能页统一使用同一条返回栈，标题栏始终提供返回上一级，关闭按钮只关闭整个面板。
- 设置页不再把工具、脚本复制成第二套入口；旧的 `configTab` 编号仍保留兼容历史状态，但不再出现在设置标签栏。插件管理从“天体数据与扩展”进入，进入后标题直接显示插件管理；脚本、命令控制和音频只从“脚本与自动化”进入。
- 插件管理只更新发生变化的插件运行态，不重载整张列表；这样不会因 ForEach 子树重建而闪屏或丢失滚动位置。功能页首次打开仍按需加载插件，并使用在途请求去重。
- 图层标签切换只更新当前标签，不对整棵图层设置树执行 `animateTo`；切换星空文化不再附带全量 `refreshState`，避免文化选择和滑动控件产生闪动。标签按钮保留轻量选中动画。
- 观测列表进入不自动启动可观测性计算；只有用户明确点击刷新才计算，并展示准备中、结果为空和超时状态。天文计算中的可观测性仍是唯一计算入口，观测工作区只承担观测目标管理。

## 源码插件盘点与后续优先级

| 优先级 | 源码插件 | 鸿蒙端策略 |
|---|---|---|
| P0 | `Oculars`、`AngleMeasure`、`PointerCoordinates`、`Satellites`、`MeteorShowers`、`TimeNavigator`、`EquationOfTime` | 已有统一功能页；继续补齐动态状态、失败反馈和 CLI 命令，不再新增重复入口 |
| P1 | `Observability`、`Calendars`、`ArchaeoLines`、`NavStars`、`Scenery3d`、`TelescopeControl`、`MosaicCamera` | 已有桥接或预留页；优先做异步计算、设备交互和离线资源状态 |
| P2 | `NebulaTextures`、`Exoplanets`、`Pulsars`、`Quasars`、`Novae`、`Supernovae`、`ObjectVisibility` | 先作为搜索分类、图层或天文计算数据源；暂不复制桌面插件窗口 |
| P3 | `SkyCultureMaker`、`SolarSystemEditor`、`LensDistortionEstimator`、`Planes`、`Vts`、`SimpleDrawLine`、`HelloStelModule` | 评估触摸编辑、模型或开发者用途后再决定是否开放；不放入普通用户的更多功能首页 |
| 离线禁用 | `OnlineQueries`、`RemoteControl`、`RemoteSync` | 未备案版本不联网；未来若开放，必须单独登记权限、端口、认证、外发字段和国内镜像/替代方案 |

插件功能与 ArkUI 功能页不是一对一复制关系：源码模块负责计算和渲染生命周期，ArkUI 负责统一交互。任何新增插件先登记唯一功能页、网络属性、CLI 命令和资源依赖，再决定是否进入菜单。

本轮使用的 ArkUI 实现遵循项目现有的响应式 Shell、状态驱动刷新和异步命令桥。当前运行环境未暴露用户配置的 `harmonyos_developer_knowledge` MCP 工具，因此没有把未验证的 MCP 返回内容写入实现或文档。
