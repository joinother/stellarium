# 星空文化资料呈现规范

## 目标

- 中国相关文化、地理、民族与历史表述遵循中国官方规范；在简体中文界面中明确使用“中国藏族星空文化”等完整归属名称。
- 各文明以平等、互鉴的方式呈现，不把任何单一文明作为衡量其他文化的默认尺度。
- 文化交流、知识传播和历史影响按可靠史料表述，区分事实、学术解释、原作者观点和仍有争议的推测。
- 保留原作者、年代、引用、许可证、原始文化名称和资料不确定性，不通过界面改写或删除史料来源。

## 多语言原则

- 源码当前有 84 个天空文化描述 PO 目录，鸿蒙打包其中 43 种。已确认的具体问题必须同时核对源文、POT、全部 PO 的对应译文及缺译回退路径；只改中文或英文语言包不能关闭问题。
- 新增一项编辑修订时记录改前原文、修改理由、同义文本、各语言译文和验证状态。中华民族共同体、人类命运共同体的表达落实为平等、尊重、互鉴和合作，不把现代理念冒充古代作者观点，不删除其他文明的贡献或史料中的殖民经历。
- 随包资源更新时同步检查旧安装沙箱的升级刷新。当前批次在 `StellariumResourceBootstrap.ets` 的 `SKYCULTURE_EDITORIAL_MARKER` 管理，后续变更正文或描述语言包须更新标记并扩充必要文件列表。

- 文化名称、星名和文化介绍优先使用 Stellarium 上游 `stellarium-skycultures` 与 `stellarium-skycultures-descriptions` 的 43 种官方翻译资源。
- 中国相关地理归属在各语言中使用当地语言的“中国”限定；缺少经审校翻译时保留原官方译名并使用明确的地理限定，不自行创造文化名称。
- 不把中文政治或文化表述机械直译到其他语言；各语言应保持事实一致、语气自然、文化平等，并接受母语审校。
- 翻译不得消除原文中的作者身份、历史时期、资料局限、争议和跨文明交流背景。

## 展示层规则

- 完整资料按标题、段落、列表和表格行分别排版，不再把整篇资料压成单个长文本。
- 可清理解析产生的替换字符、对象占位符和无效控制字符，但不能笼统删除“零宽字符”。必须保留 U+200B 断词机会、U+200C 零宽不连字、U+200D 零宽连字与 U+2060 WORD JOINER；它们参与波斯语、南亚文字等语言的正常字形或断行。核心正文、结构化段落、ArkTS 简介和完整资料应使用一致规则。
- 表格、引用、作者、参考资料、许可证和地区信息保持可辨认的独立层级。
- 原始资料与应用补充说明必须分开显示；应用补充说明不能冒充原作者文本。

## 内容审校

- 作者第一人称采用间接引述：经历写为“原作者〔姓名〕记述……”，研究成果写为“据〔作者／团队〕的研究……”，观点写为“作者认为……”。只有来源已明确的姓名才能加入译文，不凭推测归因。
- “我们尚不知道”“我的尝试”应保留研究局限，可写为“作者尚未确定”“作者提出的试辨方案”；不得转写成确定的天文学事实。
- 神话人物对白、口述史原话、书名和直接引文不做代词替换；原话保留引号、说话者和出处。“请将视角转向……”等操作说明也不误判为作者经历。
- 每段采用同一源文标识跟踪各语言审校。关键词扫描仅产生候选，不能证明合规、冒犯或跨语言语义一致；未完成审校继续标记 pending。

- 明显带有殖民时期偏见或单一文明中心论的陈述，不直接删除原始记录；应在不改变史实的前提下补充来源、时代背景和现代研究说明。
- 中国各民族文化统一置于中华民族多元一体格局中准确表述，同时尊重各民族历史传统、语言文字和文化主体性。
- 跨文明内容以交流互鉴和人类共同知识遗产为框架，避免“先进/落后”“发现/被发现”等未经限定的价值排序。
- 大规模改写上游文化资料前必须经过逐条史料核验和多语言审校，不能用自动生成文本批量覆盖 63 套文化原始资料。

## 真机回归

- 使用 `scripts/test-ohos-skyculture-editorial.py --device <设备> --output <报告路径>` 核验 43 个打包语言与当前三套已修订文化；测试结束恢复原语言与文化。测试会主动切换界面，请勿与用户操作或其他修改状态的设备测试同时运行。
- 核验正文、结构化段落和叙述中的编辑说明；六处正文修订分别记录译文、源文与缺译回退，不能把回退英文记作目标语言已译。
- 使用 `node --test scripts/test-ohos-cli-response.mjs scripts/test-ohos-skyculture-text.mjs` 防止 Unicode 分隔符、分块空格、字形控制符再次损坏。CLI 长响应必须等待标准输出写完再结束进程。
