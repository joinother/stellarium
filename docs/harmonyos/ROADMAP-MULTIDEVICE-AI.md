# 远期规划路线图：鸿蒙多设备联动 · 虚拟指星笔 · 小艺 AI · 元服务卡片

> **提出日期：** 2026-07-24
> **来源：** 用户远期产品愿景（"继续做呀，而且远期规划就是…"）
> **目标形态：** 一个 Stellarium for HarmonyOS 不只是单机星图 App，而是鸿蒙全场景天文入口——
> 手表当虚拟指星笔（你指哪颗星，其它屏就亮哪颗星）、小艺能直接帮你问星/操控星图、应用以元服务+卡片把"今夜卫星过境/天文事件"主动推给你。

## 〇、愿景拆成 4 大能力 + 落地优先级

## 一、能力 A：多设备联动 + 虚拟指星笔

### 1.1 场景
- 你戴着华为手表（或举着手机）指向夜空某个方向 → 平板/智慧屏上的 Stellarium 立刻把那颗星（或那片天区）高亮、居中、并弹出详情。
- 反向亦可：在智慧屏上选好一颗星 → 手表震一下"看那边"并给出方位角/高度角，你抬头就对着。

### 1.2 技术拆解
1. **指向数据采集（手表/手机端）**
   - 手表上的轻量 Stellarium 或独立"指星笔"元服务，用**加速度计+陀螺仪+磁力计**算出设备指向的单位向量（Alt/Az 或 J2000 方向）。
   - 鸿蒙可用 `@ohos.sensor` 拿原始 IMU，自己做姿态融合（或复用系统 `orientation` 传感器直接给方位角/俯仰角）。
2. **跨设备传输（分布式软总线）**
   - 用 **Distributed Hardware Kit / 软总线** 把"指向向量 + 时间戳"发给同账号下的目标设备（平板/智慧屏/电脑）。
   - 需要 `ohos.permission.DISTRIBUTED_DATASYNC` 等权限 + 设备组网（同一华为账号/Wi-Fi 直连）。
3. **目标设备消费（平板/智慧屏端的 Stellarium）**
   - 目标设备收到指向向量 → 调**已有命令桥** `setViewDirectionJ2000`（书签系统已用过）把视角转到那颗星 → `searchObject`/`selectAt` 选中 → 触发高亮。
   - **关键：复用现有 `StelMainView.cpp` 命令桥即可，无需改 C++ 渲染层**。手表端只是「另一个命令来源」。
4. **虚拟指星笔 UI（平板端）**
   - 在 ArkTS 侧新增"联动模式"：监听跨设备消息，实时把指向画成屏幕上的准星/光束，松手或点选即锁定该星。

### 1.3 现在就能做（不依赖华为专属 kit）
- ✅ 在 `StelMainView.cpp` 新增 `pointAtDirection <ra> <dec>` / `pointAtAltAz <alt> <az>` 命令（复用 `setViewDirectionJ2000` 逻辑），把"外部指向"标准化成内部动作——**手表端未来只是调这个命令**。
- ✅ ArkTS 侧把"指向"设计成一种输入源（和现有 dragView/zoomBy 并列），为分布式消息预留 `onRemotePointing(json)` 回调入口。
- ✅ 单机自测：用 `uitest` 或调试命令模拟"收到一个指向向量"，验证星图会转过去并高亮。

### 1.4 需要平台到位后做
- 分布式软总线组网、设备发现、跨设备权限。
- 手表端"指星笔"元服务（见能力 D）。

## 二、能力 B：小艺 AI 操控 + 问星

### 2.1 场景
- 语音/文字："那是哪颗星？" → 取当前选中/屏幕中心天体 → 小艺用自然语言回答（名字、故事、参数）。
- "放大猎户座""切换到火星视角""明天还能看到那颗彗星吗" → 小艺解析成 App 命令执行。
- "帮我设个提醒，今晚 9 点看 ISS 过境" → 落进能力 D 的卡片/提醒。

### 2.2 技术拆解
1. **自然语言 → 意图**
   - 方案 a（华为生态）：接入**小艺开放能力 / 华为 AI 云侧语义**，`onIntent` 回调拿到结构化 Intent，映射到命令桥。
   - 方案 b（先期自研、平台无关）：在 ArkTS 内做一层**轻量语义解析**（关键词/正则/小模型），先把高频指令（放大/缩小/搜索XXX/切到XXX星球/今夜事件）映射成 `callInteractive` 命令。这层**现在就能写**，且是方案 a 的降级兜底。
2. **问星问答**
   - "那是哪颗星" → 复用现有 `getSelectedObjectInfo`（已有中文结构化字段：名称/类型/星等/高度/方位/星座/距离）→ 把 JSON 拼成自然语言答复。
   - 天文知识类问题（"为什么星星会眨眼"）→ 方案 a 走小艺大模型；方案 b 先返回"暂不支持，已为你选中并展示详情"。
3. **执行闭环**
   - 解析出的命令直接走现有 `callInteractive(name, payload)` → C++ 桥 → 真实执行。

### 2.3 现在就能做（不依赖华为专属 kit）
- ✅ 在 ArkTS 新增 `aiIntentRouter(text: string)` 方法：正则/关键词匹配 → 产出 `{cmd, arg}` → 调 `callInteractive`。
- ✅ 覆盖首批指令：放大/缩小（`zoomBy`）、搜索（`searchObject`）、切星球（`setObserverPlanet`）、问"现在选中什么"（`getSelectedObjectInfo` 转自然语言）、今夜事件（见能力 C）。
- ✅ 在 UI 加一个"语音/AI 输入框"（可先用文字触发，待 CoreSpeechKit 到位接语音）。

### 2.4 需要平台到位后做
- 小艺 Intent 接入、端侧/云侧大模型问答、CoreSpeechKit 语音输入。

## 三、能力 C：应用内「今天视窗」AI 化（P0，最快出成果）

### 3.1 场景
- 打开 App 就有"今天视窗"：今晚可见行星、月相、即将过境的卫星（ISS/Starlink）、流星雨极大、日月食预告。
- 小艺能解读："今晚 9 点后猎户座升起，适合看 M42；ISS 21:14 过境亮度 -2.3"。
- 一键"带我去看"→ 自动转视角+选中+追踪。

### 3.2 技术拆解（几乎全是已有桥的编排）
- **数据源（C++ 已有，直接复用）：**
  - `getRTS` / `getAlmanac`：日月升落、晨昏、月相。
  - `getSatellites` + 卫星过境计算：ISS 等可见过境（需卫星 TLE 已加载，能力已具备）。
  - 流星雨：`getMeteorShowers`（已加桥）。
  - 天体位置：`getObjectPositions` / `getSelectedObjectInfo`。
- **编排层（ArkTS 新做）：** `buildTodayView()` 调上述命令 → 汇总成结构化"今日天文摘要" → 渲染卡片列表。
- **AI 解读（复用能力 B 的语义层）：** 把摘要喂给 `aiIntentRouter` 的"解释"分支，生成自然语言"今晚推荐"。
- **一键操作：** 每张卡片带"去看"按钮 → 调 `moveToSelected`/`setTracking`/`setObserverPlanet` 等。

### 3.3 现在就能做
- ✅ 新增「今天视窗」面板（左侧栏新按钮 + ArkTS 面板），调已有命令桥汇总渲染。
- ✅ 与能力 B 共享 `aiIntentRouter`，让"今晚看什么"能用文字触发并给出文字解读。
- ✅ 这是**纯本地、不依赖华为 kit**的，模拟器即可端到端验证。

## 四、能力 D：元服务 + 应用卡片推送

### 4.1 场景
- 不需要打开 App，锁屏/桌面卡片就显示"今晚 21:14 ISS 过境，亮度 -2.3""今晚月相 上弦""英仙座流星雨 8/12 极大"。
- 点卡片 → 拉起 Stellarium 并直接转到对应天区。
- "指星笔"做成独立元服务跑在手表上。

### 4.2 技术拆解
1. **Form Kit 卡片（应用内/桌面）：**
   - 新增 `FormExtensionAbility`，卡片布局展示"今日天文事件"；数据来自能力 C 的 `buildTodayView()`。
   - 卡片"交互事件"→ 拉起主 Ability + 带 `want.parameters` 指定要转到的天体/事件 → 主 Ability `onCreate`/`onNewWant` 解析后调命令桥执行。
2. **元服务（Atomic Service）：**
   - 把"今天视窗"或"指星笔"封装成免安装元服务，可被搜索/推荐/跨设备流转。
   - 需要**元服务上架资质 + 对应签名**，非调试环境。
3. **主动推送：**
   - 用**推送服务**或卡片定时刷新，把"今夜卫星过境"等推给用户。

### 4.3 需要平台到位后做
- FormExtensionAbility 工程、元服务签名/上架、推送服务接入。
- 当前基础 SDK 不含 Form Kit；需切到含该 kit 的 SDK 才能编译卡片工程。

## 五、分阶段执行建议（按"现在可做 / 需平台"切两刀）

### 阶段 1（现在，纯本地，模拟器可验）— 建议立即开工
1. **能力 C「今天视窗」面板**：调已有桥汇总渲染今日天文摘要（月相/行星升落/卫星过境/流星雨）。
2. **能力 B 的本地语义层 `aiIntentRouter`**：覆盖放大/缩小/搜索/切星球/问当前星/今夜事件，文字触发。
3. **能力 A 的命令桥扩展**：新增 `pointAtDirection` / `pointAtAltAz`，并把"外部指向"设计成一种输入源（预留 `onRemotePointing` 回调）。
4. 把"今天视窗"+"问星"接到一起：文字问"今晚看什么"→ 生成解读 → 可一键"去看"。

### 阶段 2（切到含华为 kit 的 SDK 后）— 接入真能力
5. **能力 B 接小艺**：语音输入（CoreSpeechKit）+ 小艺 Intent/大模型问答。
6. **能力 A 接分布式软总线**：手表指星笔 → 平板/智慧屏联动；设备发现+权限+组网。
7. **能力 D 卡片**：Form Kit 桌面卡片展示今日事件，点卡片拉起并转场。

### 阶段 3（上架资质就绪后）— 生态化
8. **能力 D 元服务**：指星笔元服务（手表）、今天视窗元服务（可被推荐/搜索/流转）。
9. **主动推送**：今夜卫星过境/天文事件主动推送给用户。

## 六、对现有代码的影响面（给执行者参考）

| 改动点 | 文件 | 说明 |
|--------|------|------|
| 新增命令桥 | `src/StelMainView.cpp` | `pointAtDirection` / `pointAtAltAz`（复用 `setViewDirectionJ2000`）；`getTodayDigest`（编排 RTS/卫星/流星雨）；`askObject`（选中天体→自然语言） |
| 语义层 | `harmonyos/ets-source/pages/MainWindowNativeNode.ets` | 新增 `aiIntentRouter(text)`、`buildTodayView()`、`onRemotePointing(json)` 入口 |
| 新面板 | 同上 | 「今天视窗」面板 + AI 输入框/语音入口 |
| 后续（阶段2/3） | 新工程模块 | FormExtensionAbility / 元服务模块 / 分布式权限配置（`module.json5` 加 `distributedNotification`、`ohos.permission.*`） |

> **核心原则：** 所有"外部输入"（语音、手表指向、卡片点击）最终都归一化到**现有 C++ 命令桥**。C++ 渲染层只认命令，不关心命令来自触摸屏、语音还是另一台设备。这保证了 A/B/C/D 之间解耦、可独立推进。

## 七、开放问题（需你/华为侧确认）
1. 工程是否能切到含 `CoreSpeechKit` / 分布式 / `Form Kit` 的华为 SDK？还是长期停留在 OpenHarmony 基础 SDK？这决定 B/A/D 的完整度上限。
2. 是否已有华为开发者账号 + 元服务上架资质？决定 D 能否走到"真推送"。
3. 手表端是"独立指星笔元服务"还是"手机投屏到手表"？影响 A 的端侧实现量。
4. 小艺接入走"小艺开放能力 Intent 框架"还是"自建语义+云侧大模型 API"？前者体验好但需华为合作，后者可控但问答能力弱。
