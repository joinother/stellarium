# 星座详情与 3D 模型预研

## 录屏交互结论

录屏中的流程是“点选星座 → 星座移动到视野中心 → 目标与详情之间保持连接关系 → 打开详情页”。详情页先展示星座名称和类型，再展示与当前星座匹配的整幅视觉资源，下面是可滚动的介绍资料。这个资源是星座图，不应被标记成真实的 3D 天体。

鸿蒙端现在采用同一套流程：星图点选星座使用 `constellation-center` 导航模式，目标移动到星图中心；详情卡继续使用当前天空文化的离线星座绘图；详情卡拖动时，连接线按目标实际投影位置实时更新。搜索、CLI 选中星座也复用中心定位，不改变行星和深空天体原有的安全区避让逻辑。

## 为什么不能直接把图片当 3D

星座是从地球视角把不同距离的恒星连接成的视觉分组，并不是一个有统一表面的物体。第一版 3D 展示只能作为“星座图形的空间化视觉层”，不能表达真实恒星距离，也不能让用户误以为星座是实体模型。因此接口明确区分：

- `image-fallback`：当前可用的天空文化绘图，保持原作者资源、文化和版权信息。
- `planned`：已定义模型资产契约，但还没有安装模型文件。
- `ready`：未来完成授权、资产校验和渲染器接入后才可使用。
- `failed`：模型存在但解码、校验或渲染失败，必须回退到图片并显示原因。

## 已预留接口

`selectedObjectJson()` 对星座返回 `detailModel`，`getObjectDetailModel` 通过 CLI 单独读取同一份契约。字段包括：

| 字段 | 用途 |
| --- | --- |
| `schemaVersion` | 协议版本，避免未来字段变化破坏旧客户端 |
| `state` | `planned`、`ready` 或 `failed` |
| `format` | 预定使用 `glTF 2.0`，实际接入时仍需检查鸿蒙图形栈支持 |
| `assetKey` | 已展开的稳定资产键：`constellations/<culture>/<iau>.glb`，例如 `constellations/modern/Ori.glb` |
| `registryPath` | 离线模型注册表 `data/ohos/detail-model-registry.json` |
| `fallbackMediaPath` | 当前文化的星座绘图回退路径 |
| `coordinateFrame` | 星图定位使用 `J2000` |
| `interactions` | 未来模型允许旋转、缩放、平移和复位 |
| `offline` | 必须为 `true`，模型不能运行时联网下载 |

当前星座详情页会标明“3D接口预留”，避免把二维绘图误称为模型。没有真实模型文件时，不能显示一个伪造的 3D 占位物。

## 后续接入顺序

1. 为单个星座准备可再分发、可离线校验的 glTF 资产和许可证记录。
2. 增加 `assetPath`、文件大小、SHA-256 和模型版本校验；校验失败继续显示文化绘图。
3. 在独立的详情媒体渲染层增加模型加载状态，不把模型加载放入星图主渲染循环。
4. 用星座中心方向作为模型锚点，详情卡拖动只改变卡片和连接线，不改变模型锚点。
5. 通过 `getObjectDetailModel`、选择事件和详情卡共享状态，补充旋转、缩放、复位的 CLI 命令。
6. 在真机上验证模型内存、纹理解码、前后台恢复和低端设备回退，再把 `state` 从 `planned` 改为 `ready`。

## 当前不做的事情

- 不把 85 个天空文化绘图替换成未经授权的模型。
- 不把星座当作真实 3D 星体，不根据模型形状推断恒星距离。
- 不引入网络瓦片或在线模型下载。
- 不重绘第二张星图；中心定位和连接线都作用于现有星图渲染层及现有详情卡。
