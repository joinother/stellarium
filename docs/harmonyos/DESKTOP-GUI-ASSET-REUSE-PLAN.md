# 原版桌面 GUI 资源复用计划

## 目标和边界

在不把 Qt Widgets 界面直接搬到 ArkUI 的前提下，复用 Stellarium 原版的图形语义、状态定义和可用视觉资产，让鸿蒙端与原版功能保持可辨识的延续性，同时满足平板、手机、键鼠和触摸的响应式交互。

- 桌面布局、Qt `.ui` 和 QSS/CSS 不直接移植。鸿蒙继续由 ArkUI 负责可访问性、触摸目标、焦点和响应式排版。
- 不将旧式位图按钮作为 Pad Dock 或底部 Dock 的完整按钮背景。它们是固定尺寸、固定阴影的桌面控件，无法适配当前 UI 的动态颜色和状态。
- 使用原版 SVG 图形或明确的原版图标语义时，保留源文件、名称和 GPL-2.0+ 许可关联；不要重新绘制成来源不明的近似图标。
- 世界地图、天空文化分布图和任何包含边界信息的素材，均须通过中国官方地理范围审查后才能作为用户可见地图。未经审查只能用于开发参考，不得进入发布界面。

## 资产结论

|主导航按钮|`data/gui/bbt*-on/off.png`|低|只参考搜索、时间、位置、设置等原始功能归类|不复用位图|

当前原版桌面 GUI 资源为 213 个文件，约 5.7 MiB；桌面 UI 逻辑位于 `src/gui/`，含 23 个 Qt `.ui` 文件。它们仍随源码和鸿蒙 rawfile 打包，但当前 ArkUI 仅使用自身 `ic_*.svg` 和独立位置地图资源。

## 实施批次

### 第一批：建立可追溯图标管线

1. 建立 `docs/harmonyos/desktop-icon-manifest.json`，逐项记录原版文件、原始图层或图标名称、ArkUI 资源名、业务动作、状态和许可来源。
2. 从 `data/gui/icons.svg` 和 `icons-compass.svg` 导出候选单图标，统一裁切到 `24x24` 逻辑画布，检查边缘、闭合路径、透明背景和单色填充兼容性。
3. 放入 `harmonyos/ets-source/resources/base/media/desktop-derived/`，命名为 `ic_desktop_<action>.svg`；禁止覆盖现有 `ic_*.svg`，直到视觉对比验收完成。
4. 完成资源同步后，在 `getIcon()` 中以显式映射进行灰度替换，不使用文件名猜测或动态字符串加载。

首批候选动作：搜索、时间、位置、设置、帮助、天文计算、观测列表、夜视、赤道仪、星座连线、星座艺术、深空图像、方位网格、赤道网格和返回当前时间。

### 第二批：核心导航和图层状态

1. 先替换平板左侧栏与手机 Dock 的六个高频入口：搜索、时间、位置、图层、观测、设置。
2. 为每项只定义 `default`、`pressed`、`selected`、`disabled`、键盘 `focused` 五种状态；图标变色承担状态表达，容器只做轻量背景和焦点描边，避免整块按钮变色。
3. 对原版 `bt*-on/off.png` 逐项建立“原版状态 - 鸿蒙动作 - 当前开关”的映射，优先覆盖夜视、赤道仪、星座线、星座图、地平线、星云、深空图、网格与时间控制。
4. 保持现有命令桥为唯一状态来源。图标状态必须由真实动作回读驱动，不能只因点击而切换视觉状态。

### 第三批：设置和天文计算

1. 对照原版 `configurationDialog.ui`、`viewDialog.ui`、`astroCalcDialog.ui` 的信息架构，补齐鸿蒙设置和天文计算入口，但不复制桌面控件密度。
2. 仅在“原版已有明确图形语义且移动端能一眼辨认”的功能中引入导出的原版图标；复杂工具用文本标题、说明和原生控件表达。
3. 时间、天文计算、图层和详情页共用同一图标映射，不为同一动作制作多个相近但含义不同的图标。

### 第四批：地理与天空文化图形

1. 单独审查 `miscWorldMap.jpg` 和 `skyCultureWorldMap.svgz` 的行政范围、名称、边界、图例与文化区域表达。
2. 若审查通过，仅将其作为底图或坐标参考；文化区域使用独立数据图层，明确其为文化研究叠加层而非政治边界。
3. 若不符合要求，保留原版数据接口与坐标逻辑，改用经审查的离线底图资源，不在发布包内直接展示原图。

## 验收标准

- 每个导出资源都在清单中可追溯到原版文件和具体功能，且没有未说明的第三方素材。
- 24、32、44、48 dp 下图标均不裁切、不插线、不与文字或相邻图标重叠。
- 默认、按下、选中、禁用和键盘焦点状态可单独辨认；状态变化不依赖色盲用户难以区分的颜色差异。
- 横屏平板、竖屏手机、鼠标悬停、键盘 Tab 和多点触摸下，图标命中区与显示位置一致。
- 图层图标的视觉状态与核心 `getActionState`/`refreshState` 回读一致；失败时恢复真实状态并显示已有失败提示。
- 地图相关资源在通过地理范围审查前不得作为发布界面素材。
- 每批完成后构建 HAP，使用模拟器和真机截图进行固定尺寸视觉回归，并更新 `RESOURCE-COVERAGE-AUDIT-2026-08-24.md`。

## 推进顺序

先完成图标清单和导出样本，再替换高频导航；随后进入图层状态，最后才处理地图和天空文化图形。这样可先改善主要操作的识别性，同时避免把未经审查的地图或旧桌面位图直接带到移动端。
