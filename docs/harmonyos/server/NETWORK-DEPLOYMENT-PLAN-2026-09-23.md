# APP 联网服务部署与备案号核查

日期：2026-09-23。范围为当前源码、生成工程、现有服务器及官方文档复核；不是所有服务已经上线的声明。

## 实际状态

- 官网已部署。`skyinstrument-resources` 仍仅在 127.0.0.1:8080 返回 `staging/publicService=false`，没有公开资源下载、同步任务或生产查询 API。
- `data/ohos/network-sources.json` 的 22 个条目是数据源，不是 22 个必须分别部署的服务。审计脚本实际通过；runtime=local-only。
- `MainWindowNativeNode.ets` 中 OFFLINE_APPGALLERY_BUILD=true，CMake 缓存 STELLARIUM_OHOS_OFFLINE=ON，源码 manifest 无 INTERNET。不能只改一个开关便宣称已联网。
- 初查源码没有备案入口；本轮核实 APP 号码后补入设置“设备与隐私”和帮助“关于”，增加共用常量的 CLI 查询。安装包验收需以新构建为准。

## 备案后的开放顺序

备案完成后不再把联网能力作为永久禁区，但采用可回退的分层开关，而不是一次性打开全部上游插件：

1. **现在可落地：** 本地代理提醒、服务卡片和本地节气/过境计算；它们不需要公网。代理提醒需 AGC 能力审批和新 Profile。
2. **第一项公网灰度：** 自有 HTTPS 版本清单、TLE/小型目录静态更新。服务端先完成真实数据同步、签名清单、ETag、限速、回退和过期提示，再加入 `INTERNET` 权限与用户主动更新入口。
3. **第二项按需联网：** 天气、ADS-B、MPC/SIMBAD、HiPS/DSS、多光谱瓦片等分别配置供应商、隐私说明和缓存，不共享一个“全部联网”开关。
4. **望远镜：** LX200/OnStep/星闪只做本地或局域网设备控制；不要为了望远镜控制新增云代理。若未来提供远程观测，再单独设计账户、鉴权和设备授权。

本轮已完成第 1 项的代理提醒基础层；第 2 项仍被服务器 staging、TLE 清单哈希不一致和数据过期阻塞，不能伪装成已上线。

## 部署决策

| 功能/现有来源 | 是否需要自建 | 落地方式与优先级 |
| --- | --- | --- |
| 卫星 TLE：stations、visual、active、SatNOGS | 优先自建统一更新分发，不是四套后端 | P1：上游许可与限频确认后，服务器定时抓取、结构/校验和/历元检查、保留来源及 partial 状态；发布版本化静态数据与可信清单。APP 主动更新，本地推算轨道/过境，不向服务器发送观测位置，不逐用户透传上游 |
| 流星雨、系外行星、新星、超新星、脉冲星、类星体六类目录 | 共用同一个静态分发服务即可 | P1：按来源许可和变更频率更新，不需要数据库、登录或每个插件独立 API；保留 QRC 随包兜底 |
| 资源版本清单 | 与上述服务一起部署 | P1：来源、资源版本、大小、SHA-256、数据历元范围、抓取时间、许可/署名和兼容性；客户端验证后按版本目录原子激活，失败用旧版。清单认证不能用下载后自己算哈希替代 |
| 深星表、高清图片、地景、天空文化、脚本数据、模型 | 基础资源不必联网 | P2：继续随包/本地导入；可选增量包超过带宽承载后再评估 OSS/CDN，不为全部基础资源强制增加下载。原生可执行插件不当作普通数据包动态分发 |
| HiPS 索引/瓦片、DSS、多光谱 | 如做境内镜像，需要独立的大资源分发规划 | P3：先许可明确的小范围离线包或受控瓦片缓存；不能只镜像目录而让 properties/瓦片继续访问境外。存储/流量实测后再购买 OSS/CDN，当前没有完整镜像 |
| SIMBAD、ASE、AAVSO、GCVS 在线查询 | 并非必须自建；如需境内代理则单独设计 | P3：遵循上游许可/限流，查询词缓存、超时和降级；不能做任意 URL 开放代理。源资料不等同于国内完整替代数据 |
| MPC 轨道目录/星历查询 | 静态目录可复用分发，动态查询另评估 | P2/P3：保留本地文件导入，确认数据授权；静态轨道与动态星历不要混同，也不把它当巡天图片 |
| 百科网页 | 不需自建全文镜像 | 用户明确点击后交给系统浏览器，说明外部站点；不自动外发资料检索词 |
| 天气/云量（后续功能） | 常需要保护供应商凭证的后端 | P3：先选定数据覆盖、许可和费用，再部署缓存代理；位置使用须单独告知，不把密钥写入 APP。当前 22 项注册表没有完整天气服务 |
| 实时飞机 ADS-B | 不能简单当静态目录镜像 | P3：确认航空数据来源、使用范围和实时费用，评估地理数据外发；当前不开放，也不宣称低频静态缓存等于实时航迹 |
| 星云纹理 Plate Solver 上传求解 | 上传服务需要独立设计 | 暂缓：本地纹理导入不需联网；在线求解涉及用户图片/可能的观测信息上传，不能随联网总开关启用 |
| 自动 IP 定位 | 不建议部署或恢复 | 保持关闭；手动地点和明确授权的系统定位已能覆盖基础用途 |
| 望远镜 LX200/星闪、多设备局域网通信 | 不需要公网云服务器 | 用户主动连接本地设备；单独管理权限、身份、端点、超时和停止控制，不将设备指令经公网中转，不依赖终端 SN |
| 本地天文通知、卫星过境计算 | 基础提醒不需要自建服务器 | Notification Kit 与代理提醒基础层已接入；卫星过境规则、TLE 新鲜度和后台真机验收仍需补齐。不能把未完成的卫星规则误归因于缺云服务器 |
| 华为 Push、远程事件提醒 | 自动化推送通常需业务后端 | 后续独立 token 注册/删除、任务发送和回执处理；PushToken 是新增数据处理项，必须告知。不是镜像服务的一部分 |
| 应用内购 IAP（若启用） | 建议独立订单/权益后端 | 服务端验证、订单/订阅事件接收、幂等与退款权益处理；密钥只在服务端。能力申请通过不等于客户端/后端已实现，不在本次部署支付服务 |
| App Linking（若启用） | 通常只需官网关联配置，未必需要新业务服务器 | 依据最终 APP 身份、签名及官方配置建立域名关联，不能猜 Profile/指纹；营销下载链接先在 AGC 核实 |
| Privacy Manager、应用市场更新 | 不自建替代后端 | 保留华为托管流程；网站部署不改变原 SN/隐私前置门禁，也不把 GitHub 上游版本当成本 APP 更新通道 |

## 现有 ECS 可以先承担什么

当前 2 核/2 GiB、3 Mbps 配置适合先验证官网加轻量目录分发，不宜据此承诺大规模并发或整套高分辨率巡天。当前七份目录实测如下（是现有旧资源的体积，不代表新数据已同步）：

| 目录 | JSON 字节数 | 单文件 gzip 字节数 |
| --- | ---: | ---: |
| 卫星 | 1,924,760 | 240,047 |
| 流星雨 | 23,097 | 3,704 |
| 系外行星 | 2,893,809 | 429,576 |
| 新星 | 14,241 | 3,090 |
| 超新星 | 7,363 | 1,676 |
| 脉冲星 | 816,801 | 176,600 |
| 类星体 | 947,495 | 178,644 |

gzip 合计约 0.99 MiB。先静态文件+版本索引+ETag/条件请求，按需只更新变化目录，不每次启动全量下载。大包维持随包，不先买新服务器、数据库、OSS/CDN；后续按真实下载量和峰值测算扩容。

## 必须修复的发布阻塞

1. 当前 satellites.json 实际 SHA-256 为 `cab4048a008dc2c77b763d773247bf66e299f03635e04bc43daa52116e2a6c14`，清单仍记录 `f82d11a95714c7c8d21b72cd6d3a25ba49f175309fc4ce66bab27f4ef7a69670`，不一致仍存在。
2. 批量 fetchedAt 仍为 2026-08-27、partial=true；已知单条补丁不能冒充整库最新。必须重建真实来源链和产物清单，不能只改日期。
3. 下载器需补强 HTTPS/重定向白名单、大小限制、超时、可信清单校验、事务激活、回退和资源过期提示。构建机更新器不能直接当生产运行时下载器。
4. 确认 APP 自身备案、实际联网能力和隐私说明后才开放运行时入口；拒绝/撤回同意、不联网、断网均能继续使用内置星图。
5. 后续用 CLI 查询来源/版本/历元/缓存/下载进度/错误码，在 Pad 验证断网、中断、空间不足、坏签名及旧版本回退。不通过放开整个上游自动网络模块冒充完成。
