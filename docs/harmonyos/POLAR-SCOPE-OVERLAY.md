已逐半秒查看用户提供的 `ScreenRecording_09-08-2026 13-35-06_1.MP4`（7.85 秒）：0–2.5 秒可见原星图和分划同步缩放，约 3–5.5 秒切换翻转。水平翻转时太阳/水星、地景和刻度左右同步变化，文字仍正向可读；底部时角、视角持续更新。视频没有完整展示进入/退出行为，也没有充分证据确认自由拖动或垂直翻转生效后的全部几何，不能把推测写成已验证。

采用其“原星图叠加分划、缩放联动、镜像一致”的处理逻辑，不采用固定屏幕大小的独立星图。录屏中缩小后的数字也明显拥挤，本实现改为按空间减少标签；顶部/底部保留悬浮控制区，不复制整块黑底。圆心代表天极，极星位于偏离天极的参考圆上，不能把北极星强行当作天极。

关闭按钮真机命中失败后，取消全屏 Transparent 多层穿透结构：星图触摸面、顶部和底部控件同属一个 Stack，根层 BLOCK_HIERARCHY，容器使用 Default，空白区域仅交给星图触摸面。再次核对华为 MCP [HitTestMode 枚举](https://developer.huawei.com/consumer/cn/doc/harmonyos-references/ts-appendix-enums#hittestmode9)确认关键根因：Block 阻塞子节点，不能放在包含按钮/开关的父容器；按钮自身可用 Block。Default 保留子节点测试并阻止下层星图接收同一点击。必须以实际触摸复测，不以 CLI 关闭成功代替按钮验收。

## 2026-09-08 缩放/拖动错位排查

Pad CLI 打开极轴镜并由 4° 放大至 1.5°，复现外环与内侧数字错位：真实天极到极星距离约 670px，外环却因上下 UI 安全区被钳制到约 433px；内圈文字仍采用真实半径。拖动时该钳制随天极屏幕位置变化，视觉上出现圆环改变尺寸、内外数字互相越位。旧实现还在天极离屏时把圆心重新放到屏幕中心，极星离屏时改用近似半径，造成不连续。

### 修订

- 保留原生星图，同一渲染线程、同一帧投影后叠加分划；不在 ArkUI 画第二层星空。
- 天极/极星均用真实投影，离开矩形视口不重置圆心或半径；进入投影背面才停止对应绘制。
- 圆环、刻度、内外数字共用未被 UI 压缩的像素半径；用二维画笔绘制仪器分划，超出视口正常裁切。此为平面极轴镜分划，不声称任意广角偏轴下仍是严格等角距天球圆。
- 根据实际字体尺寸选择刻度文字间隔；小圈省略内层文字。文字居中，剔除落入控制条或与其他文字、极星标记重叠的标签。极星名复用核心当前语言名称。
- 顶部改为居中的圆角半透明悬浮条，保留安全顶部间距、48vp 圆形关闭按钮，增加复用 centerPolarScope 的重新对准入口并恢复 4° 视场。底部资料/翻转项使用同宽悬浮卡片，不再铺满屏幕；命中测试和连接线障碍区同步更新。
- 查询华为 MCP Button 文档，使用系统 Circle 按钮，避免全宽覆盖及外层透明命中区域与按钮位置不一致；控制条最大宽 520vp，窄屏保留两侧 16vp。

## 验证与接口

`getPolarScopeData.scopeRadiusPixels` 现在与 `poleStarRadiusPixels` 一致，不再表示被安全区压缩的半径。既有 openUiPanel(polarScope)、closeUiPanel、centerPolarScope、setFOV、dragView、setActionChecked 可用于测试；真实状态以 getPolarScopeData 和截图为准，accepted 不代表完成。

没有增加联网、设备标识读取或传感器调用，主 Release 签名保持不变。
