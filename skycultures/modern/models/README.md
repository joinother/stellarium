# 3D constellation preview

82 meshes generated by the developer in Tripo from the modern culture's
illustrations. No Sky Guide mesh, material
or shader is included. The original illustrations and their attribution remain
in this culture; the developer's source ledger is `tripo-batch/archive/_manifest.csv`.
The manifest records the SHA-256 of each supplied final GLB and runtime mesh.
The supplied ledger does not establish additional Tripo service licensing terms.

Only `done` entries are packaged. Circinus is marked `done_shaky`; Columba's
bird and branch are still `done_part`. They retain illustrations. Argo Navis has
no finished model; its illustration and shared constellation anchors remain intact.
The ledger's `horologium` maps to the culture's existing `horlogium.png` spelling.
Identifiers and artwork paths come from `index.json`, not a seven-model allowlist.
The original GLBs remain untouched. Runtime copies use at most 8,000 triangles
each (configurable with `--triangle-budget`) to bound the expanded collection's
CPU projection and draw workload. This is not a measured device frame-rate guarantee.

Rebuild with Blender (no network or runtime Draco dependency):

```sh
blender --background --factory-startup -P scripts/prepare-constellation-models.py -- /path/to/tripo-batch/archive /path/to/stellarium-src/skycultures/modern
python3 scripts/test-constellation-models.py
python3 scripts/test-constellation-model-mapping.py
```

SCM1 contains little-endian vertex/index counts, six float32 values per vertex
(image-space X/Y, front-positive depth, normal XYZ), then uint32 triangle indices.
Model bounds fit the source illustration's foreground in pixel space with one
uniform scale, then X/Y are divided by image width/height respectively. This
preserves pixel aspect on non-square canvases. Depth uses the same pixel scale,
normalized by image width, matching the runtime's horizontal-span convention.
The fit is centered on the foreground bounds, not the canvas center; no extra
per-model rotation or independent X/Y stretching is applied.

The current 82 source PNGs are opaque grayscale/RGB on black. Their mask retains
every pixel with any positive RGB component, including faint or disconnected
extensions, and expands the bounding box by one pixel, clamped to the canvas.
Images with transparency instead use positive alpha, preserving black silhouettes
and ignoring RGB hidden by zero alpha. Empty masks fail export. This conservative
rule can retain stray nonzero pixels; it deliberately does not erode, filter small
components, or apply a brightness cutoff that could remove tails or thin lines.
The original Tripo preprocessing script was not available in the archive/workspace;
its input ledger records bbox dimensions but not crop offsets or a threshold.
The zero threshold is this exporter's policy, not a recovered Tripo setting.
The mapping tests include synthetic rectangular canvases, faint/disconnected
extensions and transparent black silhouettes. With Pillow installed they also
independently decode every source PNG and verify the exported bounds; without
Pillow that one integration test is explicitly skipped. The packaged-model tests
check pixel aspect, placement, containment, geometry hashes and bootstrap revision.

Each manifest entry records the source illustration hash/size, raw and padded
pixel bounds (bottom-left origin, exclusive right/top), normalized fit bounds,
mask policy, threshold, padding, and pre-fit mesh bounds. `imageBounds` remains
the normalized padded fit bounds. Source illustrations and index.json are unchanged.

Foreground fitting corrects padding/placement, not anatomical alignment. The AI
models can have different poses and front directions from the original artwork
(for example a standing lion versus the source's leaping lion). Correcting those
requires verified per-model landmark/orientation calibration or replacement assets;
the current fixed axis conversion is unchanged. Do not claim full semantic alignment
or elimination of all inter-model overlap from this correction.
The existing three Hipparcos artwork anchors determine the J2000 direction.
Depth provides self-occlusion, with a fixed soft blue-white light. Models stay
celestially anchored; this is not a freely rotating object-detail viewer.

The optional preview uses the constellation-art visibility, selection fade and
brightness. Other cultures and missing/invalid meshes retain 2D illustrations.
`setSkyCultureVisualSetting` with `constellationArt3d|1` enables the preview;
`constellationArt3d|0` restores illustrations. `getConstellationArtStatus` reports
the loaded geometry and actual mode. The setting persists locally.

HarmonyOS upgrades atomically replace each resource before Qt starts. The exporter
also generates `ConstellationModelAssets.ets` with exact file sizes and a manifest
hash revision. The completion marker changes automatically on each mesh revision;
missing/truncated files trigger repair, and a failed copy does not write the marker.
This is a bundled asset version check, not cryptographic runtime authentication.
Resource-build synchronization compares the manifest. Future exports must keep
the manifest, SCM files and generated ArkTS registry together.

`scripts/render-constellation-models.py <output.png>` generates a contact sheet
from the actual runtime meshes (requires NumPy/Pillow). It checks front-view
geometry and shading; it is not a screenshot or device performance test.
